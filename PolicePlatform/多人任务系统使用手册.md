# 多人任务系统使用手册

> 写给：策划 / 配表人员
> 用途：照着这份文档，在 Unreal 里把训练流程配出来。
> 不需要写代码，不需要懂 C++。你只需要会：新建资产、填表格、在场景里给物体打 Tag。
>
> 版本：v2.1（2026-10-26）
>
> **v2.1 配表相关的重要变化**（老用户重点看）：
> 1. 任务集精简为 **13 种**：UIPanelDisplay / WaitForConfirm / RoleSelect / EquipmentInteract / EquipmentConfirm / EquipmentAudit / StayInArea / KeepSafeDistance / StationConfirm / VoiceRecognitionWait / NPCBehavior / SearchInspection / EndTraining 等旧类型**已从代码中删除**，本手册不再描述它们。
> 2. 点击确认改用 **ClickConfirm**（客户端本地确认界面）；身份选择改用 **RoleSelect3D**（场景内 3D 选择板，锁定后系统自动给玩家贴身份 Tag）。
> 3. 新增任务类型：**TagMonitor**（标签监听）、**PlayerListener**（等齐玩家并打编号标签）、**MediaPlayback**（音频+动画组合播放，仅服务器本地）。
> 4. 提示类任务（WidgetDisplay / 生成 Actor / 改标签）**不算"任务完成"**，步骤推进只等"真正要玩家做事"的任务。步骤一推进，它们会被自动收尾（删 Widget、删道具）。
> 5. 任务系统**不再下发屏幕面板**：内置任务没有 Panel Title / Content / Rows / Buttons / Audience 这些字段了（只有 WidgetDisplay 保留"受众"概念，见第 6 章）。
> 6. 音频/动画（PlayAnim / PlayAudio）联机时客户端也能看到听到（程序侧已处理）；**MediaPlayback 例外，只在服务器本地播放**（见 7.10）。
> 7. 玩家 Pawn 需要程序打上 `VRPlayer` 或 `PCPlayer` 标签（见 4.6 备注）。

## 0. 先搞懂这套系统在干什么

整套系统只做一件事：

> **按顺序，一步一步地“等玩家做事”；某一步的所有条件都满足了，就自动进入下一步；23 步走完，训练结束。**

它不负责：

- 不负责画面怎么显示（PC 用屏幕面板、VR 用 3D 面板，都是外层框架的事）
- 不负责传送玩家、生成装备、做动画美术
- 不负责判断玩家是不是 VR

它负责：

- 判断“人有没有到位”“确认有没有点”“身份有没有锁定”“标签有没有贴上”
- 播放音频/动画并保证联机时客户端也能看到听到
- 在玩家身边显示 3D 提示、生成/删除道具、修改物体标签
- 配合外层做身份分配（谁选了什么，自动贴 Tag）

**你（策划）要交付的东西只有两个：**

1. 一个配表资产（DataAsset），里面写好 23 个步骤、每步用哪种任务、文案、扣分。
2. 场景里打好 Tag 的碰撞盒 / 站位点（有些步骤需要）。

## 1. 三个必须记住的词

### 1.1 步骤（Step）

配表里的一行。**步骤按数组从上到下顺序执行**，同一时间只会执行一个步骤。

### 1.2 任务（Task）

步骤里面装的东西。一个步骤可以装 1 个任务，也可以装 3 个任务。

### 1.3 并行（Parallel）

**同一个步骤里装的所有任务，会同时开始。**
必须这个步骤里的**所有"正事"任务都结束了**，才会进入下一步。

> v2.1：任务分两类。**正事任务**（确认/到位/选身份/标签监听/等玩家/媒体播放）必须全部完成才进下一步；**提示类任务**（WidgetDisplay / 生成 Actor / 改标签）只是陪跑的表现，不挡进度——步骤一推进，它们会被自动收尾（删提示、删道具）。

举例：

```
步骤 08
 ├─ 任务 A：等 1 号走到指定位置（GuideToLocation）
 └─ 任务 B：播放嫌疑人台词（PlayAudio）
```

上面这样配，就是“1 号一边走过去，嫌疑人一边说台词”，两个都完成才进第 09 步。

再举例（**常见错误**）：

```
步骤 03
 ├─ 任务 A：点击确认（ClickConfirm，事件说明确认）
 └─ 任务 B：点击确认（ClickConfirm，处置方式确认）
```

这样配，两个确认界面会**叠在同一个位置**，玩家根本分不清要点哪个。
**一个步骤里不要放两个“要玩家看/点”的界面任务。** 真想分两步，就拆成两个步骤。

## 2. 第一次配表：手把手从零走一遍

下面假设你要配一个只有 3 步的迷你训练。照着做一遍，你就完全会了。

### 第 1 步：新建配表资产

1. 在 Content Browser（内容浏览器）里，找一个你放配表的文件夹。
2. 右键空白处 → **Miscellaneous（杂项）** → **Data Asset（数据资产）**。
3. 弹出的列表里搜索 `PrimaryTaskDataAsset`，选中它 → 点 **Select（选择）**。
4. 给它改名，例如 `DA_Task_持械对峙_v1`。

> 看不到 `PrimaryTaskDataAsset`？说明程序还没编译，或者模块没加载，找程序。

### 第 2 步：填任务名

双击打开资产，最上面有一个 **Task Name**，填：

```
持械对峙训练
```

这个名字只用于日志和调试，玩家看不到。

### 第 3 步：加第一个步骤

找到 **Steps** 数组 → 点右边的 **+** 号，展开第 0 个元素，你会看到：

| 字段 | 填什么 |
|---|---|
| Step Id | `Step_01` |
| Step Title | `事件说明` |
| Parallel Tasks | 空数组（下一步再加） |
| Score Rules | 空数组（先不管） |

> Step Id 只是给程序/日志认的编号，建议 `Step_01` ~ `Step_23`，不要重复。
> Step Title 是中文标题，只在调试和日志里出现。

### 第 4 步：往步骤里加一个任务

展开 **Parallel Tasks** → 点 **+** → 会弹出一个类选择列表。
在搜索框输入 `WidgetDisplay`，选中 **MultipleTask WidgetDisplay**。

这时数组里出现了一个任务，展开它，你会看到一堆字段（第 7 章有每个字段的详细解释）。先填这几个：

| 字段 | 填什么 |
|---|---|
| Widget Class | 你做好的提示 UMG 控件蓝图（⚠️ 必填，不填什么都不显示） |
| Display Duration | `5`（显示 5 秒后自动消失；填 0 = 跟随步骤，本步其他事做完自动消失） |
| Attach Component Tag | 先空着（找不到附着点时自动挂在玩家 Pawn 根组件上，见 7.1） |
| Audience | `AllParticipants` |

> **注意**：WidgetDisplay 是“贴在玩家身边的世界空间 3D 提示”（VR 里浮在场景中），不是屏幕面板。提示的标题正文都在你自己的 UMG 控件里做，配表只管“显示哪个控件、显示多久、给谁看”。

### 第 5 步：加第二个步骤（等待玩家点确认）

1. 回到 Steps 数组，再点 **+**，展开第 1 个元素。
2. Step Id 填 `Step_02`，Step Title 填 `确认警情`。
3. Parallel Tasks 点 **+**，搜索 `ClickConfirm`，选中它。
4. 填：

| 字段 | 填什么 |
|---|---|
| Target Player Tags | `VRPlayer`、`PCPlayer`（哪些玩家标签需要确认，见 7.2） |
| b Require All Players | 勾上（全员确认才结束；取消 = 任一人确认即结束） |
| Widget Actor Class | 程序提供的确认界面 Actor 蓝图（必须继承 AWidgetConfirmActor） |
| Widget Spawn Transform | 确认界面出现的位置（世界坐标） |

这样就是“所有目标玩家都点了【确认】才进入下一步”。确认界面上显示什么、按钮长什么样，都在那个 Actor 蓝图里做（找程序要）。

### 第 6 步：加第三个步骤（身份选择）

1. Steps 再点 **+**，Step Id 填 `Step_03`，Step Title 填 `选择身份`。
2. Parallel Tasks 点 **+**，搜索 `RoleSelect3D`。
3. 展开 **Role Options** 数组，点 **+** 三次，分别填：

| 数组序号 | Role Tag | Display Name |
|---|---|---|
| 0 | `Role_1` | `1号 - 指挥（负责指挥、喊话、上报）` |
| 1 | `Role_2` | `2号 - 警戒（负责现场警戒、控制）` |
| 2 | `Role_3` | `3号 - 支援（负责支援与装备）` |

4. **Board Transform** 填 3D 选择板出现的位置（世界坐标，所有玩家看到的板在同一个位置）。
5. **Board Actor Class / Board Widget Class** 填程序提供的 3D 选择板蓝图（不填会用程序内置的回退样式）。

玩家在板上“选中 → 锁定”后，系统自动把 `Role_1` 这类身份 Tag 贴到他的 Pawn 上；**所有参训玩家都锁定后本步结束**。

### 第 7 步：打开日志验证

1. 保存资产。
2. 把资产交给程序（或者关卡蓝图），由框架在合适时机调用 `LoadAndStartTask`，把这份 DataAsset 传进去。
3. 进游戏（PIE 或联机测试）。
4. 打开 **Output Log**，搜索 `[TaskSequencer]`。

正常情况下你会依次看到：

```
[TaskSequencer] Loaded task: 持械对峙训练, total steps: 3
[TaskSequencer] Step 0: 事件说明 (1 parallel tasks)
[TaskSequencer] Step 1: 确认警情 (1 parallel tasks)
[TaskSequencer] Step 2: 选择身份 (1 parallel tasks)
[TaskSequencer] All steps completed!
```

看到这个，说明配表链路是通的。剩下的工作就是：把 23 个步骤按同样方法填完。

## 3. 主配表字段速查

配表资产类型：`UPrimaryTaskDataAsset`

| 字段 | 中文 | 必填 | 说明 |
|---|---|---|---|
| Task Name | 任务名 | 是 | 只用于日志/调试，建议写训练名 |
| Min Players To Start | 最少玩家数 | 否 | 默认 0 = 等首个玩家进场就开始。联机训练建议填 `1 + 远程客户端数`（如 1 主机 + 1 客户端 = 2），避免任务开始时玩家还没连上、提示/音频收不到 |
| Steps | 步骤列表 | 是 | 数组顺序 = 执行顺序。一个元素 = 一个步骤 |

### 3.1 一个步骤（Step）里有什么

| 字段 | 中文 | 必填 | 说明 |
|---|---|---|---|
| Step Id | 步骤编号 | 是 | 如 `Step_01`，不要重复 |
| Step Title | 步骤标题 | 建议填 | 中文标题，日志里显示 |
| Delay Before Start | 步骤延迟（秒） | 否 | 默认 0。填 5 = 上一步完成后**停顿 5 秒**，本步所有任务才一起开始（做节奏用） |
| Parallel Tasks | 并行任务列表 | 是 | 至少 1 个。数组里所有任务同时开始，全部"正事"结束才进下一步 |
| Score Rules | 本步评分规则 | 否 | 错误码 → 扣分值，见第 9 章 |

### 3.2 加任务项时弹出的一堆类型怎么选

快速对照（共 13 种）：

| 你想要的效果 | 选这个任务类型 |
|---|---|
| 等玩家在确认界面上点“确认”（全员或任一人） | `ClickConfirm` |
| 让玩家在场景里的 3D 选择板上选身份并锁定 | `RoleSelect3D` |
| 等 1~3 个指定身份**同时**站到各自位置 | `MultiStationArrival` |
| 等 1 个指定身份走到某个位置（带引导标志） | `GuideToLocation` |
| 等某个身份的 Pawn 被贴上指定标签（如执法记录仪开启） | `TagMonitor` |
| 等齐 N 个玩家进场，并自动给每人打编号标签 | `PlayerListener` |
| 在某个 Pawn 身上播一段动画 | `PlayAnim` |
| 播一段音频（位置音或 Pawn 音，可带说话动画） | `PlayAudio` |
| 按清单顺序播放“音频+动画”组合（⚠️ 仅服务器本地，见 7.10） | `MediaPlayback` |
| 在玩家身边显示世界空间 3D 提示（VR 里贴在场景里） | `WidgetDisplay`（提示类，不挡进度） |
| 在场景里生成一个道具（所有人可见，步骤结束可删可留） | `SpawnActor OnServer`（提示类，不挡进度） |
| 只在指定玩家的画面里生成道具（其他人看不到） | `SpawnActor OnClient`（提示类，不挡进度） |
| 给场景物体批量加/去掉标签 | `EditActorTag`（提示类，不挡进度） |

> “提示类，不挡进度”的意思：这类任务只做表现，**不用等它**。步骤里其他正事做完了它自动跟着收尾。

## 4. 场景需要提前准备什么

配表里很多字段填的是 **Tag（标签）**，不是直接拖 Actor。
Tag 的意思是：你在场景里给某个 Actor 起一个“外号”，配表里写这个外号，程序就自己去找。

### 4.1 怎么给 Actor 打 Tag

1. 在场景里选中一个 Actor（比如一个 Box Trigger）。
2. 右侧 Details（细节）面板，找到 **Actor → Tags** 数组。
3. 点 **+**，输入 Tag 名字，回车。
4. 多个 Tag 就点多次 **+**。

> Tag 名字建议用英文 + 下划线，例如 `Station_01`、`SafeArea`、`Suspect`。
> Tag **区分不了大小写**，但为了不混乱，统一大小写风格。

### 4.2 站位碰撞盒（最常用）

用于：多人到位（MultiStationArrival）、引导到位（GuideToLocation）。

做法：

1. 在场景里放一个 **Box Trigger**（Trigger Volume）。
2. 把它的大小拉到能包住“一个人站位”的范围。
3. 给它打 Tag，例如 `Station_01`。
4. 配表里把 `Station Tag` 填成 `Station_01`。

> 任务不是自己去监听碰撞，而是靠外层把 Overlap 事件转发给任务系统。
> 这一步由程序/关卡蓝图统一做，策划不需要管；**但一定要确认场景里这些碰撞盒已经接好了转发**（找程序要一份“场景 Tag 清单”来对）。

### 4.3 嫌疑人 Pawn（ASuspectPawn）

场景里会预放一个嫌疑人 Pawn（`ASuspectPawn`），它自带三样东西：

| 组件 | 干什么用 |
|---|---|
| 骨骼网格体 | 摆模型、播动画（`PlayAnim` / `PlayAudio` 直接引用它） |
| 触发框（TriggerBox） | 玩家靠近判定：只对玩家产生“进入/离开”事件、**不阻挡移动**，事件自动转发给任务系统 |
| 音频组件 | 说话/动作音效 |

要点：

- **“玩家离嫌疑人多近算靠近”不是配表里填数字，而是把嫌疑人身上的触发框拉大/拉小。**
  想要 2 米的接近判定范围，就把触发框调到 2 米。
- 想让“玩家进站”类任务以嫌疑人为目标时，给它打个 Tag（例如 `Suspect`），配表里按 Tag 找。
- 嫌疑人的动画和台词用 `PlayAnim`（Target Pawn Ref 指向它）和 `PlayAudio`（Pawn 音）来播。

### 4.4 动作 / 状态 Tag（TagMonitor 用）

标签监听（TagMonitor）不看物品的类，只看**玩家 Pawn 身上的 Tag**。

约定：

- 玩家做出某个动作（如开启执法记录仪、穿戴某件装备）→ 交互侧给玩家 Pawn 贴一个 Tag，例如 `Recorder_On`。
- 动作撤销（如关闭记录仪）→ 交互侧把这个 Tag 从 Pawn 上移除。
- 配表里 `Monitored Roles` 填的就是这些 Tag。

> 这一块需要交互/物品那边配合。策划交付前要和程序对一遍“动作 Tag 清单”。
> 场景物体也可以用 `EditActorTag` 任务在流程里自动贴/摘标签（见 7.13）。

### 4.5 身份 Tag（系统自动贴，不用你管）

玩家在 3D 选择板上**锁定**身份的瞬间，系统会自动把 `Role_1` 这类身份 Tag 贴到他的 Pawn 上（由 RoleSelect3D 任务完成，复用流程的身份分配）。
配表里所有“身份 Tag”字段，填的就是 `Role_1` / `Role_2` / `Role_3`。

### 4.6 场景 Tag 清单（建议单独维护一张表）

建议你在 Excel 里维护一份，交付时一起给程序：

| Tag | 用在哪个 Actor | 用在哪一步 | 尺寸/备注 |
|---|---|---|---|
| `Station_01` | TriggerVolume | 01 集合 | 1 人站位 |
| `Station_02` | TriggerVolume | 01 集合 | 1 人站位 |
| `Suspect` | ASuspectPawn | 09/12 | 触发框尺寸 = 接近判定范围 |
| `Recorder_On` | 玩家 Pawn（运行时） | 05/22 | 执法记录仪开启 |
| `VRPlayer` / `PCPlayer` | 玩家 Pawn（程序打） | 全程 | 程序侧负责，配表不填但会用到（如 ClickConfirm 的目标筛选） |
| ... | ... | ... | ... |

> **备注**：每个合法玩家 Pawn 需要带 `VRPlayer` 或 `PCPlayer` 标签之一，这是程序在 Pawn 生成时打的；`SpawnActor OnClient` 等任务靠它区分“真玩家”和“观战/像素流镜头”。发现玩家收不到生成物/确认界面时，先查这个标签有没有打上。

## 5. 身份（Role）和参训玩家

### 5.1 两种东西不要搞混

| 概念 | 什么时候产生 | 谁负责 |
|---|---|---|
| **参训玩家（Participant）** | 玩家进场时注册 | 外层框架调用 `RegisterParticipant` |
| **身份（Role）** | 3D 选择板上锁定身份后 | `RoleSelect3D` 任务自动分配并贴 Tag |

- 只有**参训玩家**才会收到任务下发的界面/事件，才会被“所有人都确认”“全员锁定”这类条件统计。
- 监看端/观战端不要注册，否则会永远等不到它操作。

### 5.2 身份 Tag 的规定

建议固定用三个：

```
Role_1    // 1号
Role_2    // 2号
Role_3    // 3号
```

所有任务里的 `Role Tag`、`Target Role Tags`、`Target Role Tag` 都从这里取。
**写错一个字母，对应的人就永远判定不到。**

### 5.3 缺人怎么办

- 只有 2 个玩家参训：`RoleSelect3D` 的 `Role Options` 配 3 个身份也不影响——**所有参训玩家都锁定就结束**，第 3 个身份空着无所谓。
- 但如果后面的步骤（如多人到位）配了 3 个身份的要求，第 3 个身份没人 → **这一步永远不会结束**。
  → 缺人测试时，把没人的身份从要求数组里删掉，或者保证 3 人都在。
- `TagMonitor` 的 `Monitored Roles` 配了没人的身份同理。
- 反过来，`Role Options` 数量**少于**参训人数 → 多出来的人永远锁不上身份 → 身份选择这步卡死。

## 6. 任务通用字段与"正事/提示"分类

> v2.1：内置任务**不再有屏幕面板字段**（Panel Title / Content / Rows / Buttons / Hide Panel On End 已全部删除），任务系统也不再把界面数据发给外层 UI。玩家看到的提示/界面分三种来源：
> 1. **世界空间 3D 提示** → `WidgetDisplay`（配表控制）
> 2. **客户端本地界面**（确认框 / 3D 选择板）→ `ClickConfirm` / `RoleSelect3D` 的 Actor 蓝图（程序/美术做，配表只指定用哪个蓝图）
> 3. **屏幕 UI** → 外层框架按步骤事件自行渲染，与配表无关

### 6.1 每个任务都有的字段

| 字段 | 说明 |
|---|---|
| Task Name | 任务名，只用于日志/调试，玩家看不到。建议填中文，方便排错 |

除 Task Name 外，其余字段每种任务各不相同，见第 7 章。

### 6.2 "正事任务"与"提示任务"

| 分类 | 任务类型 | 对步骤推进的影响 |
|---|---|---|
| **正事（阻塞）** | ClickConfirm、RoleSelect3D、MultiStationArrival、GuideToLocation、TagMonitor、PlayerListener、PlayAnim、PlayAudio、MediaPlayback | 必须全部完成，步骤才往下走 |
| **提示（非阻塞）** | WidgetDisplay、SpawnActor OnServer、SpawnActor OnClient、EditActorTag | 不等它；步骤推进时自动收尾（删提示/删道具） |

> 配表口诀：**每一步至少放一个"正事"任务**；全放提示类 = 这一步瞬间跳过（校验会警告）。

### 6.3 受众 Audience（目前只有 WidgetDisplay 用）

| 值 | 含义 |
|---|---|
| `AllParticipants` | 所有已注册的参训玩家（最常用） |
| `SpecificRoles` | 只发给 `Target Role Tags` 里列出的身份 |

> 单机 PIE 调试时，如果没人注册参训，`AllParticipants` 会自动退化为"本地玩家"，方便你一个人测。
> ClickConfirm 的目标筛选用的是**玩家标签**（Target Player Tags），不是 Audience，见 7.2。

### 6.4 玩家的点击是怎么回传的（给好奇的策划）

1. 服务器把"生成界面"的指令下发给目标玩家的客户端。
2. 客户端本地生成确认框 / 3D 选择板（其他人看不到你的那份）。
3. 玩家点击 → 客户端通过面板通道的**自定义事件**把结果回传服务器。
4. 服务器找到"这个事件属于哪个任务"，登记处理。

**你只需要保证：界面蓝图是程序提供的（或按附录接好线），配表里选对了蓝图类。**

## 7. 每种任务类型详细说明

> 阅读方法：每种类型先看“它是干什么的 / 什么时候结束”，再看字段表。
> 标 ⚠️ 的字段是“配错会卡住/跳过”的高危项。

### 7.1 WidgetDisplay —— 世界空间 3D 提示（提示类）

**一句话**：在受众玩家的 Pawn 身上（头顶/胸前等附着点）挂一个你做的 UMG 控件，作为场景内的 3D 提示；不接收任何点击。

**什么时候结束**：

- `Display Duration > 0`：显示 N 秒后自动移除并结束。
- `Display Duration = 0`（默认）：**跟随步骤**——本步其他正事全部结束、步骤推进时自动移除（推荐用法）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Widget Class** | 是 | 空 | ⚠️ 要显示的 UMG 控件蓝图，不填什么都不显示 |
| Display Duration | 否 | `0` | 持续秒数；0 = 跟随步骤生命周期 |
| b Draw At Desired Size | 否 | 不勾 | 按控件自身期望尺寸绘制 |
| Draw Size | 条件 | `300×150` | 上项不勾时的绘制尺寸 |
| Attach Component Tag | 建议 | 空 | 在玩家 Pawn 身上找带这个 Tag 的 SceneComponent 当附着点；找不到就兜底挂 Pawn 根组件（位置可能不对） |
| Audience | 是 | `AllParticipants` | 发给谁 |
| Target Role Tags | 条件 | 空 | Audience=SpecificRoles 时生效 |

**常见配错**：

- Widget Class 忘填 → 这一步“什么都没发生”。
- Audience = SpecificRoles 但 Target Role Tags 空 → 没有受众，谁也看不到。
- 附着点 Tag 在玩家 Pawn 身上不存在 → 提示挂在腰上/脚底（根组件位置），不会报错。
- 想同时放两个提示 → WidgetDisplay 可以并行多个（不同附着点/不同受众），不冲突。

**示例**：02 步警情通报 → 挂在 1 号头顶，5 秒自动消失。

---

### 7.2 ClickConfirm —— 等玩家点确认

**一句话**：在目标玩家的画面里生成一个确认界面（每个客户端本地一份，别人看不到），全员（或任一人）点“确认”后结束。

**什么时候结束**：

- `b Require All Players` 勾选（默认）：**所有目标玩家**都确认 → 结束。
- 不勾：**任意一个目标玩家**确认 → 结束（如“清点完毕”只需一人报）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Target Player Tags** | 是 | 空 | ⚠️ 哪些玩家标签的 Pawn 需要确认（如 `VRPlayer`、`PCPlayer`）。写错 = 有人没有界面，全员模式永远凑不齐 |
| **b Require All Players** | 是 | 勾选 | 全员确认才结束 / 任一确认即结束 |
| **Widget Actor Class** | 是 | 空 | ⚠️ 确认界面 Actor 蓝图，**必须继承 AWidgetConfirmActor**（找程序要；界面样式都在这个蓝图里） |
| Widget Spawn Transform | 是 | 0 | 确认界面生成位置（世界坐标） |
| b Destroy On End | 否 | 勾选 | 结束后自动销毁客户端确认界面 |

**工作方式**：服务器广播“生成”→ 目标玩家客户端本地生成界面 → 玩家点击 → 结果回传服务器登记 → 条件满足即结束并统一销毁所有界面。

**常见配错**：

- Widget Actor Class 没填，或不是 AWidgetConfirmActor 的子类 → 没有界面可点，流程卡死。
- Target Player Tags 漏了某个玩家用的标签 → 那个人没有界面。
- 同一步骤放两个 ClickConfirm → 两个界面叠在同一个位置（见 1.3 的常见错误）。

**示例**：03 步“请确认现场情况” → 全员；装备清点后的“清点完毕” → 不勾全员（任一人）。

---

### 7.3 RoleSelect3D —— 3D 选择板选身份

**一句话**：在场景固定位置生成一块 3D 选择板（每个客户端本地一份），玩家“选中 → 锁定”；**所有参训玩家都锁定后结束**，锁定瞬间系统自动给该玩家的 Pawn 贴身份 Tag。

**规则**：

- 一人同时只能占用一个身份；被占用的选项别人选不了；**未锁定可以取消**释放。
- **锁定后不可更改**（不能反悔）；锁定 = 贴 Tag = 这个人的身份在流程里正式生效。
- 结束条件：所有**已注册参训玩家**都锁定；断线的玩家保持占用。
- 锁定后身份 Tag 的用法见 4.5——后面的到位/监听任务都按它判定。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Role Options** | 是 | 空 | ⚠️ 每项：`Role Tag` + `Display Name`（显示名）。Tag 不可重复、不可为空 |
| Board Actor Class | 建议 | 空 | 3D 板 Actor 蓝图（客户端本地生成）；不填用程序内置回退样式 |
| Board Widget Class | 建议 | 空 | 板上显示的 UMG 控件；不填由蓝图自行设置 |
| Board Transform | 是 | 0 | 板的生成位置（固定世界坐标，所有玩家看到同一块板） |

**常见配错**：

- `Role Tag` 和后面任务里写的身份不一致（如这里 `1号`、后面 `Role_1`）。
- `Role Options` 数量少于参训人数 → 多出来的人永远锁不上身份，卡死。
- Board Transform 配进墙里/地下 → 板看不见（不会报错，用 `Task.Debug 1` 核对位置）。

**示例**：04 步三个身份。客户端蓝图怎么接线见文末附录。

---

### 7.4 MultiStationArrival —— 多人“同时”到位

**一句话**：要求 N 个身份**同时**站在各自的碰撞盒里。

**什么时候结束**：`Requirements` 里所有身份**同一时刻**都处于各自站位 → 立即结束。
任何一个人离开，他的到位状态会被取消（但通常此时任务已经结束了）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Requirements | 是 | 空 | 每个元素：`Role Tag` + `Station Tag` |

> 配 1 个元素 = 单人到位；配 3 个 = 三人同时到位。
> ⚠️ 数组里任何一个 `Station Tag` 在场景里找不到 → **任务直接结束（被跳过）**，日志会警告。
> ⚠️ 身份没有对应玩家 → 这个身份永远不到位 → 任务卡死。

**常见配错**：

- 场景碰撞盒 Tag 打错一个字母。
- 以为“到位”是累计的：“1号先到、离开、2号再到”不会完成，必须是同一时刻。
- 想让“所有人到同一个位置” → 这个任务做不了“共享站位”，把每个人的站位碰撞盒分开摆，一人一个 Tag。

**示例**：01 步三人到集合点；13 步三人到指定位置。

---

### 7.5 GuideToLocation —— 单人走到指定位置（带引导标志）

**一句话**：等 1 个身份进入 1 个碰撞盒；可以在碰撞盒上方生成一个引导标志（箭头/光环）。

**什么时候结束**：该身份一进入碰撞盒 → 立即结束。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Station Tag | 是 | 空 | 目标碰撞盒 Tag |
| Required Role Tag | 是 | 空 | 要求哪个身份进去 |
| Show Marker | 否 | 勾选 | 是否生成引导标志 |
| Marker Class | 条件 | 空 | 引导标志的 Actor 类（不填就不生成） |
| Marker Height Offset | 否 | `50` | 标志离碰撞盒顶面的高度（厘米） |

**常见配错**：

- 勾了 Show Marker 但没填 Marker Class → 不会有标志（不会报错）。
- 需要一个身份到位但填了 `Required Role Tag` 为空 → 谁进去都不算。

---

### 7.6 TagMonitor —— 标签监听

**一句话**：低频轮询指定身份的玩家 Pawn 有没有被贴上指定标签，贴上即满足；用于“做动作 → 贴标签 → 监听”的通用场景（如执法记录仪开启、装备穿戴确认）。

**什么时候结束**：

- `b Require All Roles` 勾选（默认）：**所有列出的身份**都满足 → 结束。
- 不勾：**任意一个身份**满足 → 结束。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Monitored Roles** | 是 | 空 | ⚠️ 身份 → 标签列表。该身份的 Pawn 贴上列表里**任意一个**标签即视为满足（见 4.4 的约定） |
| **b Require All Roles** | 是 | 勾选 | 所有身份满足 / 任一身份满足 |
| Check Interval | 否 | `0.5` | 轮询间隔（秒），一般不用改 |

**常见配错**：

- 交互侧根本没往 Pawn 上贴标签 → 永不满足，卡死（先和程序对“动作 Tag 清单”，见 4.4）。
- 配了某个身份，但场上没有这个身份的人 → 永不满足。
- 标签拼写和交互侧约定不一致。

**示例**：06 步“领取装备” → 每个身份监听各自的装备 Tag；22 步装备清点同理。

---

### 7.7 PlayerListener —— 等齐玩家并打编号标签

**一句话**：任务启动时立即扫描已在场的合法玩家，并持续监听后续进场的玩家；给每位匹配到的玩家 Pawn 打上“前缀+编号”的标签，等齐 N 人后自动结束。

**典型用法**：配在第 0 步，让流程**不等齐玩家直接开跑**，由本任务自己负责等齐 N 人后再放行到后续步骤（配合程序把“最少玩家数”设为 1）。

**什么时候结束**：匹配到的玩家数量达到 `Required Player Count` → 结束。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Filter Tags | 否 | 空 | 玩家 Pawn 须带其中**任意一个**标签才纳入；**留空 = 放行全部**（含观战/像素流镜头，慎用） |
| **Required Player Count** | 是 | `2` | 等齐几个玩家 |
| **Base Tag To Assign** | 是 | 空 | 标签前缀；自动拼自增编号（例：`Player` → `Player1`、`Player2`、`Player3`…） |
| Poll Interval | 否 | `0.5` | 兜底轮询间隔（秒），一般不用改 |

**注意**：

- 这里的 `Filter Tags` 是本任务自己的筛选条件，和全局的 `VRPlayer/PCPlayer` 是两套配置，互不影响。
- 玩家 Pawn 中途销毁重生的话，新 Pawn 上的编号标签**不会自动补**——重开本任务或让程序在重生时补发。

**常见配错**：

- Filter Tags 留空 → 把观战镜头也算进“玩家”，可能提前凑齐。
- Base Tag To Assign 忘填 → 打不出标签，后续按标签找人的任务全部判不到。

**示例**：00 步 `Base Tag To Assign = Player`、`Required Player Count = 3`，等三人进齐再开始正式流程。

---

### 7.8 PlayAnim —— 在指定 Pawn 上播动画

**一句话**：在某个身份/NPC 身上播放一段或多段动画。

**什么时候结束**：

- `Wait Anim End` 勾选（默认）：等动画时长走完（多段则依次播完）后结束。
- `Wait Anim End` 不勾：动画开始播放后**立即结束任务**（动画继续播）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Need Multiple Anim | 否 | 不勾 | 勾上=播数组里的多段动画 |
| Play Anim Info | 条件 | 空 | 单段动画配置 |
| Play Anim Info Array | 条件 | 空 | 多段动画配置 |
| Target Role Tag | 条件 | 空 | 播给哪个身份 |
| Target Pawn Ref | 条件 | 空 | 直接指定 Pawn（用于 NPC） |
| Wait Anim End | 是 | 勾选 | 是否等播完 |
| Loop Count | 是 | `1` | 1=播一次；N=播 N 次；**0 = 无限循环** |

**常见配错**：

- `Loop Count = 0` 且 `Wait Anim End` 勾选 → 任务永远不结束。⚠️
- 目标 Pawn 身上没有 SkeletalMesh → 任务直接结束（不会播）。
- 同时填了 `Target Role Tag` 和 `Target Pawn Ref` → 优先用身份。

---

### 7.9 PlayAudio —— 播放音频序列

**一句话**：按数组顺序播放音频，可以指定“位置音”或“跟着某个 Pawn 播”。

**什么时候结束**：数组里所有音频播完（自动结束）。

**字段（每条音频）**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Play Sound | 是 | 空 | 音频资产 |
| Play Audio Type | 是 | `PlayAudioForLocation` | 位置音 / Pawn 音 |
| Play Audio Location | 条件 | 0 | 位置音的世界坐标 |
| Target Role Tag | 条件 | 空 | Pawn 音按身份找目标 |
| Play Audio Pawn | 条件 | 空 | Pawn 音直接指定 Pawn |
| Need Play Anim | 否 | 不勾 | 播音频时是否同时播动画 |
| Play Audio Sequence | 条件 | 空 | 同时播的动画 |
| Delay Before Playback | 否 | `0` | 这条开始前等几秒 |
| Delay After Playback | 否 | `0` | 这条播完后等几秒再播下一条 |

**行为细节**：

- 某一条的目标找不到 / 音频为空 → 跳过这条继续下一条（会打警告）。
- `PlayAudioForLocation` 播完会自动销毁音频组件。

**常见配错**：

- 位置音填了坐标，但关卡坐标和场景对不上（比如用了相对坐标思路）。
- 想“语音一响玩家就能听到”，结果位置音放在了另一个房间。

---

### 7.10 MediaPlayback —— 音频+动画组合播放（清单式）

**一句话**：按清单顺序逐条播放“音频 / 动画 / 音频+动画”组合，一条播完（含前后延迟）再播下一条，全部播完结束。

> ⚠️ **重要限制**：这个任务**只在服务器本地播放**——联机时其他客户端看不到也听不到。
> 只适合单机调试或服务器本地演示。要让所有玩家看到/听到，用 `PlayAnim` + `PlayAudio`（它们走网络广播，客户端正常）。

**什么时候结束**：清单里所有条目播完（自动结束）。

**字段（Playlist 的每一项）**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Sound | 否 | 空 | 要播的音频（可与动画同配一条） |
| Anim Sequence | 否 | 空 | 要播的动画 |
| Location Type | 是 | `AtLocation` | 世界固定坐标 / 挂在 Pawn 身上 |
| Location | 条件 | 0 | 固定坐标（AtLocation 时用） |
| Target Role Tag | 条件 | 空 | 按身份找 Pawn（OnPawn 时优先） |
| Target Pawn Ref | 条件 | 空 | 直接指定 Pawn（如嫌疑人） |
| Delay Before / Delay After | 否 | `0` | 本条开始前 / 结束后的延迟（秒） |
| b Wait Anim End | 否 | 勾选 | 是否等这条的动画播完才进入收尾 |
| Loop Count | 否 | `1` | 动画循环次数（1=单次，0=无限 ⚠️） |

**常见配错**：

- Playlist 为空 → 任务立即结束（等于没配）。
- 位置类型选了固定坐标，却配了动画 → **动画不会播**（动画只能挂在 Pawn 上），校验会警告。
- 按 Pawn 播但身份和 Pawn 引用都没填 → 校验报错。
- `Loop Count = 0` 且等动画播完 → 永不结束。

**示例**：17 步嫌疑人“后退 + 台词 + 抬手”一组动作 → 三条 Playlist 顺序播放（单机演示场景）。

### 7.11 SpawnActor OnServer —— 生成道具（所有人可见，提示类）

**一句话**：在服务器按世界坐标生成一个 Actor，自动同步给所有客户端（包括中途加入的人）。

**什么时候结束**：生成就算完成——它是提示类任务，**不挡步骤推进**；步骤结束（EndTask）时按 `b Destroy On Step End` 决定删除还是保留。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Actor Class** | 是 | 空 | ⚠️ 要生成的蓝图类，不填什么都不生成 |
| Spawn Transform | 是 | 0 | 生成位置/旋转/缩放（世界坐标） |
| b Destroy On Step End | 否 | 勾选 | 步骤结束删 / 留（勾掉 = 保留给后续流程用或手动清理） |

**注意**：同一个蓝图类如果被 `SpawnActor OnClient` 用来本地生成，两边互不干扰（这里实例级开复制，那边本地关复制）。

**示例**：支援车辆开进现场 → 车辆蓝图生成在路边。

---

### 7.12 SpawnActor OnClient —— 生成道具（仅指定玩家可见，提示类）

**一句话**：在匹配玩家的客户端上**本地**生成一个 Actor，其他玩家看不到；互不影响。

**什么时候结束**：同 OnServer——不挡步骤推进，步骤结束时按配置删/留。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Actor Class** | 是 | 空 | ⚠️ 要生成的蓝图类（客户端要能加载到它） |
| Spawn Transform | 是 | 0 | 生成位置（世界坐标） |
| Target Filter Tag | 否 | 空 | 只在带此标签的玩家客户端生成；**空 = 所有合法玩家（VRPlayer/PCPlayer）都生成** |
| b Destroy On Step End | 否 | 勾选 | 步骤结束删 / 留 |

**注意**：

- 玩家中途加入**不会补生成**（和音频一样属瞬态表现）。
- 生成的 Actor 是纯本地表现，服务器上没有对应实例，不要指望它参与服务器判定。

**示例**：给 1 号的视野里生成一个只有他能看到的证物标记。

---

### 7.13 EditActorTag —— 批量改标签（提示类）

**一句话**：找到场景里所有带某标签的 Actor，一次性给它们加上/移除另一个标签；做完立即结束。

**什么时候结束**：改完立即结束（一次性动作，不挡步骤推进）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| **Find Tag** | 是 | 空 | ⚠️ 查找标签：所有带它的 Actor 都会被处理 |
| Operation | 是 | Add Tag | 添加 / 移除 |
| **Tag To Modify** | 是 | 空 | ⚠️ 要加/删的标签 |

**注意**：

- 只处理**开启复制**的 Actor（否则服务器加了标签客户端没有，出现两端不一致，会打警告）。
- 常和 `TagMonitor` 配合：本任务贴标签 → TagMonitor 监听到 → 步骤推进。
- 只对 Actor（场景物体）生效；给**玩家 Pawn** 贴标签的活归 `PlayerListener`（编号标签）和 `RoleSelect3D`（身份标签）。

**示例**：任务开始时给现场门禁加 `Unlocked` 标签，配合交互侧开门。

## 9. 评分配置

### 9.1 分数怎么算

- 每个身份初始 **100 分**（评分组件的 `Base Score`）。
- 每上报一次错误码，按该错误码的 `Penalty` 扣分。
- 最低 0 分，不会扣成负数。
- 同一身份可以多次扣分（`Violation Count` 记录次数，`Violated Error Codes` 去重记录触发过哪些错误码）。

### 9.2 在哪配规则

配在 **Step 的 `Score Rules`** 数组里：

| 字段 | 说明 |
|---|---|
| Error Code | 错误码，必须和任务里填的**完全一致** |
| Description | 中文说明（报表/调试用） |
| Penalty | 扣几分（正整数） |

> 查找顺序：先查“当前步骤”的规则，再查整张表的规则。
> 所以规则配在哪个步骤都能生效，但**建议配在会触发它的那个步骤**，便于阅读。

### 9.3 当前任务集没有内置错误码

> v2.1：随旧任务类型删除，**当前 13 种任务没有内置错误码**——没有任何任务会“自动”上报扣分。

所有扣分都由外部（程序侧的交互/识别/监控系统）调用 `ReportScoreEvent(角色, 错误码)` 主动上报。
你在 `Score Rules` 里配的规则，就是为这些“外部上报”准备的标准：**错误码叫什么、扣几分，由你和程序一起约定**。

- 漏配规则不会崩溃：按 0 分记录并打日志（见 9.4）。
- 任务里没有“Violat­ion Error Code”这类字段了——错误码的来源在交互侧代码里，不在配表里。

### 9.4 漏配规则会怎样

- 不会崩溃。
- 该次上报按 **0 分**处理，日志出现：
  ```
  [Score] Error code xxx has no score rule in current task, recorded with 0 penalty
  ```
- 看到这条日志，说明你的配表漏了规则或错误码写错了。

### 9.5 推荐配法（示例）

错误码名字是**和程序约定的自定义字符串**，下面只是示例：

| Error Code | Description | Penalty |
|---|---|---|
| `RecorderNotOn` | 未按要求开启执法记录仪 | 10 |
| `WrongHandling` | 处置方式选择错误 | 15 |
| `LeaveStation` | 擅自离开指定站位 | 10 |

> 约定原则：全大写单词 + 下划线或驼峰，**错误码在“上报方代码”和“Score Rules”两处必须一字不差**。

## 10. 十个最容易配错的地方（必看）

> 下面每一条都可以先用第 11 章的 `Task.Validate` 自动查一遍，能省掉大半人工排查。

### ① 任务不往下走了，日志只有“Step 开始”

按顺序检查这 4 项：

1. **这一步的“正事”任务的完成条件是什么？**
   - `ClickConfirm`：目标玩家标签写全了吗？全员/任一模式选对了吗？
   - `RoleSelect3D`：是不是还有人没在板上锁定身份？
   - `TagMonitor`：要监听的标签有人往 Pawn 上贴吗（交互侧接了吗）？
2. **站位类任务的 `Role Tag` 是不是都有人？**
   - 少一个人，就少一个“到位”。
3. **`PlayAnim` 的 `Loop Count` 是不是 0 且等播完？**
   - 0 = 无限循环，任务永不结束。
4. **`MediaPlayback` 的清单是不是空的？**
   - 空清单会立即结束（不是卡住），但等于什么都没播。

### ② 任务一闪而过 / 直接跳过

- `MultiStationArrival` 的 `Station Tag` 场景里找不到 → 任务**直接结束**（被跳过），日志有警告。
- 某一步全是提示类任务（WidgetDisplay / 生成 Actor / 改标签）→ 这一步瞬间过。

### ③ 玩家点了确认没反应

- 确认界面蓝图没接回传（`ReportConfirmed` / 自定义事件上报）→ 找程序按文末附录接线。
- 玩家不是 `Target Player Tags` 的目标 → 他界面上根本没有确认框。
- 界面已被销毁（任务结束自动清理），点到的是残影。

### ④ 两个界面叠在一起

- 同一个步骤里放了两个 `ClickConfirm`（或一个 ClickConfirm 一个 3D 选择板挤在同一位置）。
- **一个步骤只放一个“要玩家点”的界面任务**，其余拆到下一步。

### ⑤ 玩家永远选不到身份 / 选完卡住

- `RoleSelect3D` 的 `Role Options` 少于参训人数 → 多出来的人锁不上。
- 身份 `Role Tag` 前后不一致（`Role1` vs `Role_1`）。
- 有人没注册成参训玩家 → 板上锁了也不算数（程序侧确认）。

### ⑥ 标签监听永不满足

- 交互侧根本没往 Pawn 上贴标签（先对“动作 Tag 清单”，见 4.4）。
- 配了某个身份，但场上没有这个身份的人。
- 标签拼写和交互侧约定不一致。

### ⑦ 世界空间提示不显示 / 位置不对

- `Widget Class` 没填 → 什么都不显示。
- `Attach Component Tag` 在玩家 Pawn 身上找不到 → 兜底挂根组件，位置不对（让程序在 Pawn 身上放一个带 Tag 的挂点）。
- `Audience = SpecificRoles` 但 `Target Role Tags` 空 → 没有受众。

### ⑧ 联机时客户端听不到 / 看不到

- 用了 `MediaPlayback` → 它**只在服务器本地播放**，换 `PlayAnim` + `PlayAudio`。
- `SpawnActor OnClient` 对中途加入的玩家不补生成。
- 音频/动画都是“开始那一刻在场才能看到听到”的瞬态表现，中途加入不补播。

### ⑨ 生成的道具有人看不到

- 用的是 `SpawnActor OnClient` → 只有匹配 `Target Filter Tag` 的玩家本地生成，别人看不到是**正常的**；要所有人可见用 `SpawnActor OnServer`。
- 玩家 Pawn 上没有 `VRPlayer/PCPlayer` 标签 → 被“合法玩家”过滤掉了（见 4.6 备注）。

### ⑩ 全部步骤走完了，训练却没结束

- 任务系统只广播“所有步骤完成”（`OnAllStepsCompleted`），**不负责切场景/重开/结束页**（原 EndTraining 已删除）。
- 框架没绑定这个事件 → 找程序。

## 11. 调试工具（配表出问题先跑这个）

配表配错时，最常见的表现是「**流程卡住，日志里什么错都没有**」。
系统内置了一个调试工具，专门解决这个问题。全部功能都在**控制台**里用，不需要改代码、不需要重启工程。

> 这个工具只在**编辑器 / 开发版**里存在，正式打包发布（Shipping）不会带上，对成品没有任何影响。

### 11.0 第一步永远是：跑一次自检

1. 启动 PIE（或单机运行），确保任务配表已经加载。
2. 按键盘 **`~`**（Esc 下面那个键）打开控制台。
3. 输入：

```
Task.Validate
```

4. 回车。控制台会逐条列出问题，最后一行是汇总。

输出长这样：

```
===== 配表校验：DA_持械对峙 =====
[错误] Step[06] Step_06 / MultipleTask_MediaPlayback | Playlist[0] 按 Pawn 播放但既没有身份也没有 Pawn引用
[警告] Step[00] Step_00 / MultipleTask_MultiStationArrival | 场景中找不到带 Tag Station_01 的站位碰撞盒
[提示] Step[01] Step_01 / MultipleTask_WidgetDisplay | AttachComponentTag 为空，Widget 将直接挂在 Pawn 根组件上
汇总：错误 1，警告 1，提示 1
```

**三条级别怎么理解：**

| 级别 | 意思 | 要不要处理 |
|---|---|---|
| `[错误]` | 一定会导致流程卡死 / 跳过 / 无法完成 | **必须改**，否则跑不通 |
| `[警告]` | 大概率配错了，但流程还能走 | 强烈建议改 |
| `[提示]` | 建议项 | 看情况，可以忽略 |

> 如果控制台提示 `没有可校验的配表`，说明任务还没开始。先让游戏跑到任务启动，或者用第 11.3 节的指定路径方式校验。

### 11.1 全部命令一览

打开控制台输入 **`Task.Help`**，会打印下面这张表。

| 命令 | 怎么用 | 干什么 |
|---|---|---|
| `Task.Help` | `Task.Help` | 列出所有命令 |
| `Task.Validate` | `Task.Validate` 或 `Task.Validate /Game/路径/DA_XXX` | 配表自检（见上一节） |
| `Task.Dump` | `Task.Dump` | 打印整张配表的步骤和任务清单 |
| `Task.Skip` | `Task.Skip 8` | 直接跳到指定步骤（**从 0 开始数**，`Task.Skip 8` = 第 9 步） |
| `Task.Finish` | `Task.Finish All` / `Task.Finish PlayAudio` | 结束当前步骤里活跃的任务 |
| `Task.Restart` | `Task.Restart` | 用当前配表重新开始整个训练 |
| `Task.Roles` | `Task.Roles` | 查看谁是几号身份、谁还没选 |
| `Task.Panels` | `Task.Panels` | 查看每个玩家当前收到的是什么面板 |
| `Task.Scores` | `Task.Scores` | 查看当前每个人的分数和扣分记录 |
| `Task.Debug` | `Task.Debug 1` / `Task.Debug 0` | 打开 / 关闭场景可视化 |

> 输入命令时**不区分大小写**，`task.validate` 和 `Task.Validate` 一样。

### 11.2 `Task.Dump` —— 确认配表到底长什么样

最常用的第二个命令。它会把你配的表原样打印出来，用来确认「我是不是漏加了某一步」「这个任务到底是不是我选的那个类型」。

```
Task.Dump
```

```
===== 持械对峙（共 23 步）=====
[00] Step_00  事件接收与初步判断
      TaskName  <MultipleTask_WidgetDisplay>
[01] Step_01  现场分工
      TaskName  <MultipleTask_RoleSelect3D>
[02] Step_02  领装
      TaskName  <MultipleTask_TagMonitor>
      -5  RecorderNotOn  (未开记录仪)
```

看懂三件事：

- 方括号里是**步骤序号**，从 0 开始。
- `<...>` 里是**任务类名**，对应第 7 章的类型说明。
- 缩进的 `-5 EquipmentMissing` 是**这一步的评分规则**。

如果打印出来的类名和你以为的不一样，说明加任务时选错类型了——这是很常见的配错。

### 11.3 `Task.Validate` 指定路径校验（不开游戏也能查）

不想进 PIE，只想检查一张配表？把资产路径直接写上。

1. 在 Content Browser 里右键配表资产 → **Copy Reference**。
2. 控制台输入：

```
Task.Validate /Game/TaskSystem/DA_持械对峙.DA_持械对峙
```

> 路径格式必须是 `/Game/...` 开头、带 `.资产名` 结尾。
> 复制出来的引用如果带引号，把引号去掉再粘。

这种方式**不需要任务正在运行**，但「场景里有没有这个 Tag」这类检查需要当前关卡，所以建议还是进 PIE 后再跑一次。

### 11.4 卡住的时候怎么用 `Task.Skip` / `Task.Finish`

**场景：** 走到第 9 步不动了，你想知道后面配得对不对。

```
Task.Skip 8
```

直接跳到第 9 步（**序号从 0 开始**：第 1 步是 `Task.Skip 0`，第 9 步是 `Task.Skip 8`）。

**场景：** 某个「等玩家操作」的任务永远等不到人操作（比如某个确认任务），你想让它先过去。

```
Task.Finish ClickConfirm
```

按**类名的一部分**匹配，不用写完整类名。也可以一次结束当前步骤的全部任务：

```
Task.Finish All
```

匹配不到时会提示 `没有匹配的活跃任务`，此时用 `Task.Dump` 看看当前到底有哪些任务。

> `Task.Skip` 和 `Task.Finish` 只影响当前这一局，不会改你的配表。刷新 PIE 就恢复原样。

### 11.5 `Task.Restart` —— 反复调试不用重开 PIE

改完配表之后，不必关掉 PIE 再重来：

```
Task.Restart
```

会用**当前加载的同一张配表**重新从头跑。适合反复验证某一个改动点。

> 如果改的是资产里的字段，记得先保存资产（Ctrl+S），`Task.Restart` 读的是内存里的资产内容。

### 11.6 `Task.Roles` —— 谁是谁

怀疑「身份分配」出问题时用：

```
Task.Roles
```

```
===== 参训玩家 3 人 =====
  PlayerA → Role_1
  PlayerB → Role_2
  PlayerC → <未分配>
  已占用身份：Role_1, Role_2
```

- `<未分配>` 的玩家就是**导致「所有人选完身份」这一步过不去**的元凶。
- 如果这里显示 0 人，说明**参训玩家根本没注册**——这是程序侧的事（见文末「给程序的交接信息」），不是你配表的问题。

### 11.7 `Task.Panels` —— 面板通道状态

> v2.1：内置任务**不再通过面板通道下发屏幕面板**；确认框 / 3D 选择板是客户端本地界面，**不在这里显示**。这条命令现在主要用于确认“面板通道组件在不在”。

```
Task.Panels
```

```
===== 面板状态（3 人）=====
  PlayerA：可见=否
  PlayerB：可见=否
  PlayerC：没有面板通道组件
```

| 看到什么 | 说明 |
|---|---|
| `可见=否` | 正常——内置任务不发屏幕面板；只有外层框架自己下发的面板才会显示“是” |
| `没有面板通道组件` | 该玩家没被注册为参训玩家（程序侧）——确认框/选择板这类交互他**都收不到** |

### 11.8 `Task.Scores` —— 分数对不对

验证评分规则有没有生效：

```
Task.Scores
```

```
===== 评分板（3 条）=====
  Role_1：得分 95，扣分 5，异常 1 次，错误码：RecorderNotOn
  Role_2：得分 100，扣分 0，异常 0 次
  Role_3：得分 100，扣分 0，异常 0 次
```

如果**做了违规动作却没有记录**，检查这个错误码在对应步骤的 `Score Rules` 里有没有同名规则（见 9.4）。

### 11.9 `Task.Debug 1` —— 把场景里的 Tag 全画出来

这是最直观的功能。输入：

```
Task.Debug 1
```

游戏画面上会多出：

| 显示 | 含义 |
|---|---|
| 绿色文字 | Actor 身上的 Tag（每个 Tag 一行，浮在物体上方） |
| 青色线框 | 当前任务正在用的**站位碰撞盒**（多人到位 / 引导到位引用的 Tag） |
| 红色 `MISSING TAG: xxx` | 配表里写了这个 Tag，但**场景里找不到** |
| 左上角文字 | 当前第几步、有哪些任务在跑（`[√]`=已完成 /`[…]`=运行中）、“正事”完成进度、谁是谁的身份、缺失 Tag 列表 |

**最重要的用法：看到红色 `MISSING TAG`，就等于直接告诉你「配表的 Tag 和场景对不上」。**

关闭：

```
Task.Debug 0
```

> 这个开关默认是关的。它只在你自己的开发机上显示，不影响别人。

### 11.10 一个完整的排错流程

照着这个顺序走，99% 的卡死都能定位：

```
第 1 步   Task.Validate          → 有没有 [错误]？有就直接改
第 2 步   Task.Dump              → 当前步骤的任务类型选对了吗？
第 3 步   Task.Roles             → 三个人的身份都分配了吗？
第 4 步   Task.Panels            → 三个人的面板通道都在吗（参训注册了吗）？
第 5 步   Task.Debug 1           → 场景里有没有红色 MISSING TAG？
第 6 步   Task.Finish All        → 能过去吗？能过去说明就是这一步的任务没被满足
```

### 11.11 自检能查出哪些问题（对照表）

`Task.Validate` 会覆盖下面这些，**带 ⚠ 的都是会让流程卡死的高危项**：

| 任务类型 | 检查内容 |
|---|---|
| 所有任务 | 步骤为空、步骤 ID 未填 / 重复、步骤里没有任务、空任务项 |
| ⚠ `MultiStationArrival` | 要求表为空、身份/站位 Tag 为空、站位在场景里找不到 |
| `GuideToLocation` | 站位 Tag 为空或找不到、身份 Tag 为空、开了引导但没配标志类 |
| ⚠ `MediaPlayback` | 清单为空；条目既没音频也没动画；按 Pawn 播却没身份没引用；延迟为负；配了动画但位置类型是固定坐标（动画不会播） |
| ⚠ `WidgetDisplay` | Widget 类为空；SpecificRoles 但名单为空；绘制尺寸非正 |
| ⚠ `SpawnActor OnServer` | Actor 类为空；生成缩放接近零 |
| ⚠ `SpawnActor OnClient` | Actor 类为空；目标筛选标签为空（提示所有合法玩家都会生成）；生成缩放接近零 |
| `EditActorTag` | 查找标签为空、要改的标签为空 |
| 评分 | 校验框架已就位；当前任务集没有内置错误码，此项暂不产出结果（新任务扩写时补充） |

> 没有专门校验项的任务（ClickConfirm / RoleSelect3D / TagMonitor / PlayerListener / PlayAnim / PlayAudio）也会跑“所有任务”那一行的基础检查；它们的字段问题靠 `Task.Dump` 人工核对。

### 11.12 常见疑问

**Q：控制台打不开？**
A：先用鼠标点一下 PIE 窗口让它获得焦点，再按 `~`（Esc 下面那个键）。有些键盘布局需要按 `Ctrl + ~`，也可以直接在编辑器菜单 `Window → Output Log` 底部的命令行输入。

**Q：提示「找不到 Sequencer」？**
A：说明任务驱动器还没创建（任务还没开始）。等进入训练场景后再执行。

**Q：`Task.Validate` 报了一堆 [提示]，需要全改吗？**
A：不用。只处理 `[错误]`，`[警告]` 挑和自己场景相关的看。`[提示]` 只是建议。

**Q：这些命令会把配表改坏吗？**
A：不会。所有命令都是只读查看，或者只影响当前这一局运行状态；配表资产一个字都不会动。

**Q：正式版能用吗？**
A：不能，也不应该。工具在 Shipping 包里不存在。

## 13. 术语表

| 名词 | 意思 |
|---|---|
| DataAsset / 配表 | 你在 Content Browser 里建的那个 `PrimaryTaskDataAsset` 资产 |
| Step / 步骤 | 配表里的一行，按顺序执行 |
| Task / 任务项 | 步骤里装的一个具体任务 |
| Parallel Tasks / 并行任务 | 同一个步骤里同时执行的任务列表 |
| Role / 身份 | `Role_1` / `Role_2` / `Role_3`，由 3D 选择板锁定后自动分配 |
| Participant / 参训玩家 | 进场时注册过的玩家；只有他们收界面/事件、参与“全员”判定 |
| Tag / 标签 | 挂在 Actor 上的字符串标记，配表用 Tag 找物体 |
| TriggerVolume / 碰撞盒 | 场景里用来判断“人有没有进去”的盒子 |
| Overlap / 重叠 | 玩家进入/离开碰撞盒的事件 |
| Panel / 面板通道 | 挂在 PlayerState 上的收发组件（程序侧）；内置任务现在只用它收发**自定义事件**（确认/选择结果），不再发屏幕面板 |
| Custom Event / 自定义事件 | 客户端和服务器互传事件的通用通道：上行 `SubmitCustomEvent`，下行 `NotifyCustomEvent`（程序侧） |
| Audience / 受众 | 3D 提示发给谁：所有参训玩家 / 指定身份（目前只有 WidgetDisplay 用） |
| Error Code / 错误码 | 评分用的字符串标识，如 `RecorderNotOn` |
| Penalty / 扣分 | 每个错误码扣多少分 |
| Sequencer / 任务驱动器 | 挂在 GameState 上、负责按步骤跑任务的组件（程序侧） |

## 附：给程序的交接信息（策划可忽略）

配表以外的部分由程序完成：

- 在玩家进场时调用 `UTaskSequencerComponent::RegisterParticipant(PC)`；离开时 `UnregisterParticipant`。
- 在合适时机调用 `LoadAndStartTask(DataAsset)`。
- 关卡 TriggerVolume / 嫌疑人 TriggerBox 的 Overlap 事件转发到 `ForwardOverlapBegin` / `ForwardOverlapEnd`。
- 玩家身上的**面板通道**（`UTaskPanelChannelComponent`）按需使用：上行 `SubmitCustomEvent(EventId, Payload)` 报结果（会转发给当前任务），下行 `NotifyCustomEvent(EventId, Payload)` 给客户端 UI 发指令（客户端绑 `OnCustomEventNotified` 收）。
- 外部事件需要强制结束某类任务时：`FinishActiveTasksByClass(UMultipleTask_ClickConfirm::StaticClass())`（换成对应任务类即可）。
- 框架绑定 Sequencer 的 `OnAllStepsCompleted` 处理训练结束（返回列表 / 重新训练）。
- 评分板读取 `UScoreComponent::GetAllScores()`，绑定 `OnScoreBoardChanged` 刷新。

### 3D 选择板（RoleSelect3D）客户端接入三件套

身份选择任务把 3D UI 放在每个客户端本地生成，服务器只管权威状态。客户端需要三样东西（缺一不可，详见开发文档 7.13）：

1. **`ARoleSelectBoard`**（C++ 壳 Actor，客户端本地生成、不经复制）：持有 `WidgetComponent`；`SpawnBoardFromPayload` 一站式解析 Spawn 事件并生成；`ParseStatePayload` 解析状态；`RequestSelectRole / RequestCancelRole / RequestLockRole` 转成上行事件；`OnBoardEvent` 把通道下发事件转发给 WBP。
2. **BP_BoardSpawner**（建在 PlayerController 蓝图里，常驻监听）：BeginPlay 绑本地通道 `OnCustomEventNotified`；收到 `Role3D_Spawn` 调 `SpawnBoardFromPayload` 并把 Board 存成变量；收到 `Role3D_Close` 销毁。它存在的意义：Board 出生之前没人能听到 Spawn 指令，必须由常驻的 PC 代听。
3. **WBP_RoleSelectBoard**：绑 `OnBoardEvent`，收到 `Role3D_State` 调 `ParseStatePayload` 刷新按钮（Free=可点，Occupied/Locked=置灰并显示占用者）；点击通过 Board 的 `RequestSelectRole / RequestCancelRole / RequestLockRole` 上报（内部走 `SubmitCustomEvent`）。

下行事件：`Role3D_Spawn`（生成）/ `Role3D_State`（全量状态）/ `Role3D_Close`（销毁）；上行事件：`Role3D_Select / Role3D_Cancel / Role3D_Lock`（Payload 即 RoleTag）。
