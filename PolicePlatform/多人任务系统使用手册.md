## 0. 先搞懂这套系统在干什么

整套系统只做一件事：

> **按顺序，一步一步地“等玩家做事”；某一步的所有条件都满足了，就自动进入下一步；23 步走完，训练结束。**

它不负责：

- 不负责画面怎么显示（PC 用屏幕面板、VR 用 3D 面板，都是外层框架的事）
- 不负责传送玩家、生成装备、做动画美术
- 不负责判断玩家是不是 VR

它负责：

- 判断“人有没有到位”“按钮有没有点”“装备有没有拿”“话有没有说对”
- 把提示面板的数据发给玩家
- 玩家违规时给对应的人扣分

**你（策划）要交付的东西只有两个：**

1. 一个配表资产（DataAsset），里面写好 23 个步骤、每步用哪种任务、文案、扣分。
2. 场景里打好 Tag 的碰撞盒 / 站位点（有些步骤需要）。

## 1. 三个必须记住的词

### 1.1 步骤（Step）

配表里的一行。**步骤按数组从上到下顺序执行**，同一时间只会执行一个步骤。

### 1.2 任务（Task）

步骤里面装的东西。一个步骤可以装 1 个任务，也可以装 3 个任务。

### 1.3 并行（Parallel）

**同一个步骤里装的所有任务，会同时开始。**
必须这个步骤里的**所有任务都结束了**，才会进入下一步。

举例：

```
步骤 08
 ├─ 任务 A：NPC 走到指定位置（NPCBehavior）
 └─ 任务 B：播放嫌疑人台词（MediaPlayback）
```

上面这样配，就是“NPC 一边走，一边说台词”，两个都完成才进第 09 步。

再举例（**常见错误**）：

```
步骤 03
 ├─ 任务 A：显示“请确认现场情况”面板
 └─ 任务 B：显示“请选择处置方式”面板
```

这样配，两个面板会**抢同一个显示位置**，后发的覆盖先发的。
**一个步骤里不要放两个“要玩家看/点”的面板任务。** 真想分两步，就拆成两个步骤。

## 2. 第一次配表：手把手从零走一遍

下面假设你要配一个只有 3 步的迷你训练。照着做一遍，你就完全会了。

### 第 1 步：新建配表资产

1. 在 Content Browser（内容浏览器）里，找一个你放配表的文件夹。
2. 右键空白处 → **Miscellaneous（杂项）** → **Data Asset（数据资产）**。
3. 弹出的列表里搜索 `PrimaryTaskDataAsset`，选中它 → 点 **Select（选择）**。
4. 给它改名，例如 `DA_Task_持械对峙_v1`。

> 看不到 `PrimaryTaskDataAsset`？说明程序还没编译，或者模块没加载，找程序。

### 第 2 步：填任务名

双击打开资产，最上面有一个 **Task Name**，填：

```
持械对峙训练
```

这个名字只用于日志和调试，玩家看不到。

### 第 3 步：加第一个步骤

找到 **Steps** 数组 → 点右边的 **+** 号，展开第 0 个元素，你会看到：

| 字段 | 填什么 |
|---|---|
| Step Id | `Step_01` |
| Step Title | `事件说明` |
| Parallel Tasks | 空数组（下一步再加） |
| Score Rules | 空数组（先不管） |

> Step Id 只是给程序/日志认的编号，建议 `Step_01` ~ `Step_23`，不要重复。
> Step Title 是中文标题，只在调试和日志里出现。

### 第 4 步：往步骤里加一个任务

展开 **Parallel Tasks** → 点 **+** → 会弹出一个类选择列表。
在搜索框输入 `UIPanelDisplay`，选中 **MultipleTask UIPanelDisplay**。

这时数组里出现了一个任务，展开它，你会看到一堆字段（第 7 章有每个字段的详细解释）。先填这几个：

| 字段 | 填什么 |
|---|---|
| Panel Type | `EventInfo` |
| Panel Title | `警情通报` |
| Panel Content | `接群众报警，某小区住户持械对峙，请立即前往处置。` |
| Panel Rows | 先空着 |
| Panel Buttons | 先空着 |
| Audience | `AllParticipants` |
| Auto Close Delay | `5`（5 秒后自动关闭并进入下一步） |

### 第 5 步：加第二个步骤（等待玩家点确认）

1. 回到 Steps 数组，再点 **+**，展开第 1 个元素。
2. Step Id 填 `Step_02`，Step Title 填 `确认警情`。
3. Parallel Tasks 点 **+**，搜索 `WaitForConfirm`，选中它。
4. 填：

| 字段 | 填什么 |
|---|---|
| Panel Title | `警情确认` |
| Panel Content | `请确认已了解警情内容。` |
| Confirm Button Text | `已了解` |
| Confirm Policy | `AllPlayers` |
| Audience | `AllParticipants` |

这样就是“所有参训玩家都点了【已了解】才进入下一步”。

### 第 6 步：加第三个步骤（身份选择）

1. Steps 再点 **+**，Step Id 填 `Step_03`，Step Title 填 `选择身份`。
2. Parallel Tasks 点 **+**，搜索 `RoleSelect`。
3. 展开 **Roles** 数组，点 **+** 三次，分别填：

| 数组序号 | Role Tag | Display Name | Description |
|---|---|---|---|
| 0 | `Role_1` | `1号 - 指挥` | `负责指挥、喊话、上报` |
| 1 | `Role_2` | `2号 - 警戒` | `负责现场警戒、控制` |
| 2 | `Role_3` | `3号 - 支援` | `负责支援与装备` |

4. **Require All Participants** 勾上（默认就是勾上的）。
5. Audience 选 `AllParticipants`。

### 第 7 步：打开日志验证

1. 保存资产。
2. 把资产交给程序（或者关卡蓝图），由框架在合适时机调用 `LoadAndStartTask`，把这份 DataAsset 传进去。
3. 进游戏（PIE 或联机测试）。
4. 打开 **Output Log**，搜索 `[TaskSequencer]`。

正常情况下你会依次看到：

```
[TaskSequencer] Loaded task: 持械对峙训练, total steps: 3
[TaskSequencer] Step 0: 事件说明 (1 parallel tasks)
[TaskSequencer] Step 1: 确认警情 (1 parallel tasks)
[TaskSequencer] Step 2: 选择身份 (1 parallel tasks)
[TaskSequencer] All steps completed!
```

看到这个，说明配表链路是通的。剩下的工作就是：把 23 个步骤按同样方法填完。

## 3. 主配表字段速查

配表资产类型：`UPrimaryTaskDataAsset`

| 字段 | 中文 | 必填 | 说明 |
|---|---|---|---|
| Task Name | 任务名 | 是 | 只用于日志/调试，建议写训练名 |
| Default Equipment By Role Tag | 默认装备映射 | 否 | `身份Tag → 装备信息`。目前仅作为以后扩展用的数据表，任务流程不依赖它 |
| Steps | 步骤列表 | 是 | 数组顺序 = 执行顺序。一个元素 = 一个步骤 |

### 3.1 一个步骤（Step）里有什么

| 字段 | 中文 | 必填 | 说明 |
|---|---|---|---|
| Step Id | 步骤编号 | 是 | 如 `Step_01`，不要重复 |
| Step Title | 步骤标题 | 建议填 | 中文标题，日志里显示 |
| Parallel Tasks | 并行任务列表 | 是 | 至少 1 个。数组里所有任务同时开始，全部结束才进下一步 |
| Score Rules | 本步评分规则 | 否 | 错误码 → 扣分值，见第 9 章 |

### 3.2 加任务项时弹出的一堆类型怎么选

快速对照：

| 你想要的效果 | 选这个任务类型 |
|---|---|
| 只给玩家看一段文字/信息 | `UIPanelDisplay` |
| 等玩家点某个按钮 | `WaitForConfirm` |
| 让玩家自己选 1号/2号/3号 | `RoleSelect` |
| 等 1~3 个指定身份同时站到各自位置 | `MultiStationArrival` |
| 等 1 个指定身份走到某个位置（带引导标志） | `GuideToLocation` |
| 等玩家把指定装备都拿到身上 | `EquipmentInteract` |
| 展示全员装备并等人点确认，锁定装备 | `EquipmentConfirm` |
| 核对装备是否符合标准并扣分 | `EquipmentAudit` |
| 监听玩家是否贴上了指定标签（如执法记录仪开启） | `TagMonitor` |
| 玩家必须待在某个区域内（离开就算违规） | `StayInArea` |
| 玩家必须离嫌疑人足够远（靠近就算违规） | `KeepSafeDistance` |
| 三人全部就位后，任意一人点确认 | `StationConfirm` |
| 等某个身份说对话，并检查关键词 | `VoiceRecognitionWait` |
| 让 NPC 走位/等待/播动画/说话 | `NPCBehavior` |
| 播一段音频、动画或两者的组合 | `MediaPlayback` |
| 搜身（按部位依次检查） | `SearchInspection` |
| 结束训练，给“返回列表/重新训练”两个按钮 | `EndTraining` |

> **注意**：原 `PlayAnim` 和 `PlayAudio` 已合并为 `MediaPlayback`，不再单独存在。

## 4. 场景需要提前准备什么

配表里很多字段填的是 **Tag（标签）**，不是直接拖 Actor。
Tag 的意思是：你在场景里给某个 Actor 起一个“外号”，配表里写这个外号，程序就自己去找。

### 4.1 怎么给 Actor 打 Tag

1. 在场景里选中一个 Actor（比如一个 Box Trigger）。
2. 右侧 Details（细节）面板，找到 **Actor → Tags** 数组。
3. 点 **+**，输入 Tag 名字，回车。
4. 多个 Tag 就点多次 **+**。

> Tag 名字建议用英文 + 下划线，例如 `Station_01`、`SafeArea`、`Suspect`。
> Tag **区分不了大小写**，但为了不混乱，统一大小写风格。

### 4.2 站位碰撞盒（最常用）

用于：多人到位、就位确认、引导到位、警戒区域。

做法：

1. 在场景里放一个 **Box Trigger**（Trigger Volume）。
2. 把它的大小拉到能包住“一个人站位”的范围。
3. 给它打 Tag，例如 `Station_01`。
4. 配表里把 `Station Tag` 填成 `Station_01`。

> 任务不是自己去监听碰撞，而是靠外层把 Overlap 事件转发给任务系统。
> 这一步由程序/关卡蓝图统一做，策划不需要管；**但一定要确认场景里这些碰撞盒已经接好了转发**（找程序要一份“场景 Tag 清单”来对）。

### 4.3 区域（警戒区 / 安全距离区）

- **警戒待命（StayInArea）**：区域 = 一个带 Tag 的碰撞盒，例如 `SafeArea`。玩家必须留在里面。
- **保持安全距离（KeepSafeDistance）**：区域 = 嫌疑人 Pawn 自己身上的碰撞盒（`ASuspectPawn` 自带的 TriggerBox），Tag 默认是 `Suspect`。
  - **安全距离不是配表里填数字，而是在场景里把嫌疑人的碰撞盒拉大/拉小。**
  - 想让“安全距离 2 米”，就把那个 Box 的半径调到 2 米。

### 4.4 装备 Tag

装备判定不看装备 Actor 的类，只看**玩家 Pawn 身上的 Tag**。

约定：

- 玩家拿起某件装备 → 物品类给玩家 Pawn 贴一个 Tag，例如 `Equip_Shield`。
- 玩家丢下 → 物品类把这个 Tag 从 Pawn 上移除。
- 配表里 `Required Tags` 填的就是这些 Tag。

> 这一块需要物品/交互那边配合。策划交付前要和程序对一遍“装备 Tag 清单”。

### 4.5 身份 Tag（系统自动贴，不用你管）

玩家在 04 步选了 `Role_1`，系统会自动把 `Role_1` 贴到他的 Pawn 上。
配表里所有“身份 Tag”字段，填的就是 `Role_1` / `Role_2` / `Role_3`。

### 4.6 场景 Tag 清单（建议单独维护一张表）

建议你在 Excel 里维护一份，交付时一起给程序：

| Tag | 用在哪个 Actor | 用在哪一步 | 尺寸/备注 |
|---|---|---|---|
| `Station_01` | TriggerVolume | 01 集合 | 1 人站位 |
| `Station_02` | TriggerVolume | 01 集合 | 1 人站位 |
| `SafeArea` | TriggerVolume | 07/16 警戒 | 覆盖整个警戒区 |
| `Suspect` | ASuspectPawn | 09/12 | 碰撞盒半径 = 安全距离 |
| `Equip_Shield` | 玩家 Pawn（运行时） | 05/06/22 | 防暴盾 |
| ... | ... | ... | ... |

## 5. 身份（Role）和参训玩家

### 5.1 两种东西不要搞混

| 概念 | 什么时候产生 | 谁负责 |
|---|---|---|
| **参训玩家（Participant）** | 玩家进场时注册 | 外层框架调用 `RegisterParticipant` |
| **身份（Role）** | 04 步玩家自己选 | `RoleSelect` 任务自动分配 |

- 只有**参训玩家**才会收到面板、才会被“所有人都确认”这类条件统计。
- 监看端/观战端不要注册，否则会永远等不到它点按钮。

### 5.2 身份 Tag 的规定

建议固定用三个：

```
Role_1    // 1号
Role_2    // 2号
Role_3    // 3号
```

所有任务里的 `Role Tag`、`Target Role Tags`、`Speaker Role Tag` 都从这里取。
**写错一个字母，对应的人就永远判定不到。**

### 5.3 缺人怎么办

- 只有 2 个玩家参训：04 步 `Require All Participants` 勾上，两个人都选到身份就结束，第 3 个身份空着不影响。
- 但如果 06 步（装备检查）配了 3 个身份的要求，第 3 个身份没人 → **这一步永远不会结束**。
  → 缺人测试时，把没人的身份从要求数组里删掉，或者保证 3 人都在。

## 6. 所有面板任务的通用字段

带“面板”的任务都继承同一套字段（`UIPanelDisplay`、`WaitForConfirm`、`RoleSelect`、`EquipmentConfirm`、`StationConfirm`、`StayInArea`、`KeepSafeDistance`、`EndTraining`）。

### 6.1 面板类型 Panel Type

只是告诉外层 UI “该用哪套皮肤”，任务系统不决定显示方式。

| 值 | 用在哪 |
|---|---|
| `EventInfo` | 事件说明、结束页 |
| `RoleSelect` | 身份选择 |
| `InjuryReport` | 伤情上报 |
| `EquipmentCheck` | 装备清点/选装 |
| `ScenePrompt` | 场景提示、警告、就位确认 |
| `Custom` | 其它（默认值） |

> 选错了不会坏，只是 UI 皮肤可能不对。拿不准就选 `ScenePrompt`。

### 6.2 内容字段

| 字段 | 说明 |
|---|---|
| Panel Title | 面板大标题 |
| Panel Content | 面板正文（一段话） |
| Panel Rows | 静态数据行（Label / Value / ValueColor），用于“伤情列表”“装备清单”这类 |
| Panel Buttons | 静态按钮（ButtonId / Label / Description / bEnabled / DisabledReason） |

> Row 的 `ValueColor` 只影响颜色，不影响逻辑。

### 6.3 发给谁 Audience

| 值 | 含义 |
|---|---|
| `AllParticipants` | 所有已注册的参训玩家（最常用） |
| `SpecificRoles` | 只发给 `Target Role Tags` 里列出的身份 |

> 单机 PIE 调试时，如果没人注册参训，`AllParticipants` 会自动退化为“本地玩家”，方便你一个人测。

### 6.4 结束时是否关闭面板

`Hide Panel On End` 默认勾选。不要关掉，否则任务结束后面板还挂在玩家脸上。

### 6.5 按钮是怎么回传的

1. 服务器把面板数据发给玩家。
2. 玩家点按钮 → 客户端把 `ButtonId` 回传服务器。
3. 服务器找到“这个按钮属于哪个任务”，调用它的处理逻辑。

**你只需要保证：按钮的 `Button Id` 和任务里约定的 Id 一致。**
比如 `WaitForConfirm` 的确认按钮固定回传 `Confirm`，你额外加的静态按钮不会触发确认。

## 7. 每种任务类型详细说明

> 阅读方法：每种类型先看“它是干什么的 / 什么时候结束”，再看字段表。
> 标 ⚠️ 的字段是“配错会卡住/跳过”的高危项。

---

### 7.1 UIPanelDisplay —— 只展示信息

**一句话**：给玩家看一段文字，看完自动关；不接收任何点击。

**什么时候结束**：

- `Auto Close Delay > 0`：显示 N 秒后自动关闭并结束。
- `Auto Close Delay = 0`：**永远不结束**，必须由外部（框架）调用结束。⚠️ 配表时除非程序明确说会外部结束，否则一定要填大于 0。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Panel Type | 建议 | `Custom` | 面板皮肤 |
| Panel Title | 是 | 空 | 标题 |
| Panel Content | 是 | 空 | 正文 |
| Panel Rows | 否 | 空 | 数据行 |
| Panel Buttons | 否 | 空 | **点了也没反应**（纯展示任务不处理按钮） |
| Audience | 是 | `AllParticipants` | 发给谁 |
| Target Role Tags | 条件 | 空 | Audience=SpecificRoles 时生效 |
| Hide Panel On End | 是 | 勾选 | 结束时关闭面板 |
| **Auto Close Delay** | 是 | `0` | ⚠️ 0 = 永不自动结束 |

**常见配错**：

- 忘记填 Auto Close Delay → 流程卡在这一步，日志只有 Step 开始没有完成。
- 想在展示面板上放一个“继续”按钮 → 这个任务不处理按钮，应该改用 `WaitForConfirm`。

**示例**：02 步警情通报 → 5 秒自动关闭。

---

### 7.2 WaitForConfirm —— 等玩家点确认

**一句话**：发一个带确认按钮的面板，等到“该点的人”都点了就结束。

**什么时候结束**：按 `Confirm Policy` 判定满足后立即结束。

| Confirm Policy | 结束条件 |
|---|---|
| `AllPlayers` | **所有已注册参训玩家**都点过 |
| `AnyPlayer` | 任意 1 人点过 |
| `SpecificRoles` | `Specific Role Tags` 里列出的身份都点过 |
| `FirstRole_1` | `Role_1` 点过（不管别人） |

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Panel Title | 是 | 空 | 标题 |
| Panel Content | 建议 | 空 | 正文 |
| Panel Rows | 否 | 空 | 附加数据行 |
| Panel Buttons | 否 | 空 | 额外按钮（不会触发确认） |
| Audience | 是 | `AllParticipants` | 发给谁 |
| Hide Panel On End | 是 | 勾选 | 结束时关闭 |
| **Confirm Button Text** | 是 | 空 | 确认按钮文字。⚠️ 留空 = 不生成按钮 = 玩家没法点 |
| **Confirm Policy** | 是 | `AllPlayers` | 见上表 |
| Specific Role Tags | 条件 | 空 | 仅 SpecificRoles 用 |

**常见配错**：

- `Confirm Button Text` 没填 → 面板上没按钮，流程卡死。
- `Confirm Policy = SpecificRoles` 但 `Specific Role Tags` 是空的 → 立即判定通过（0 >= 0），面板一闪而过。
- 玩家没注册参训却用 `AllPlayers` → 单机会退化成“本地玩家”，联机时可能永远凑不齐。
- 用 `FirstRole_1` 但 04 步没分配出 `Role_1` → 永远等不到。

**示例**：03 步“请确认现场情况” → AllPlayers；21 步“处置完成，请确认” → AnyPlayer。

### 7.3 RoleSelect —— 玩家自己选身份

**一句话**：把可选身份做成按钮发给大家，谁点谁占，占过的置灰。

**什么时候结束**：

- `Require All Participants` 勾选（默认）：**所有已注册参训玩家都拿到身份**后结束。
- `Require All Participants` 不勾：**配置的身份全部被占用**后结束（不是“谁先选谁赢”）。
- `Roles` 为空：立刻结束（会警告）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Roles | 是 | 空 | 每个元素：Role Tag / Display Name / Description |
| Require All Participants | 是 | 勾选 | 见上 |
| Rejected Selection Content | 否 | 空 | 抢一个已被占用的身份时，给该玩家的提示文案 |
| Panel Title / Content | 建议 | 空 | 面板标题正文 |
| Audience | 是 | `AllParticipants` | 必须发给所有人，否则没人能选 |
| Panel Type | 建议 | `Custom` | 建议手动改成 `RoleSelect` |
| Hide Panel On End | 是 | 勾选 | 结束时关闭 |

**常见配错**：

- `Roles` 里的 Role Tag 和后面任务里写的身份不一致（如这里 `1号`、后面 `Role_1`）。
- 只配 2 个身份，却要求 3 个玩家都选 → 第 3 个人永远选不到，卡死。
- `Audience` 改成 `SpecificRoles` → 没收到面板的人无法选择。

**示例**：04 步三个身份。

### 7.4 MultiStationArrival —— 多人“同时”到位

**一句话**：要求 N 个身份**同时**站在各自的碰撞盒里。

**什么时候结束**：`Requirements` 里所有身份**同一时刻**都处于各自站位 → 立即结束。
任何一个人离开，他的到位状态会被取消（但通常此时任务已经结束了）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Requirements | 是 | 空 | 每个元素：`Role Tag` + `Station Tag` |

> 配 1 个元素 = 单人到位；配 3 个 = 三人同时到位。
> ⚠️ 数组里任何一个 `Station Tag` 在场景里找不到 → **任务直接结束（被跳过）**，日志会警告。
> ⚠️ 身份没有对应玩家 → 这个身份永远不到位 → 任务卡死。

**常见配错**：

- 场景碰撞盒 Tag 打错一个字母。
- 以为“到位”是累计的：“1号先到、离开、2号再到”不会完成，必须是同一时刻。
- 想让“所有人到任意一个区域” → 这个任务做不到，用 `StayInArea` 或拆开配。

**示例**：01 步三人到集合点；13 步三人到指定位置。

### 7.5 GuideToLocation —— 单人走到指定位置（带引导标志）

**一句话**：等 1 个身份进入 1 个碰撞盒；可以在碰撞盒上方生成一个引导标志（箭头/光环）。

**什么时候结束**：该身份一进入碰撞盒 → 立即结束。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Station Tag | 是 | 空 | 目标碰撞盒 Tag |
| Required Role Tag | 是 | 空 | 要求哪个身份进去 |
| Show Marker | 否 | 勾选 | 是否生成引导标志 |
| Marker Class | 条件 | 空 | 引导标志的 Actor 类（不填就不生成） |
| Marker Height Offset | 否 | `50` | 标志离碰撞盒顶面的高度（厘米） |

**常见配错**：

- 勾了 Show Marker 但没填 Marker Class → 不会有标志（不会报错）。
- 需要一个身份到位但填了 `Required Role Tag` 为空 → 谁进去都不算。

### 7.6 EquipmentInteract —— 装备检查 / 领取装备

**一句话**：轮询玩家 Pawn 上的 Tag，所有配置的身份都拿齐了要求装备就结束。

**什么时候结束**：所有 `Requirements` 满足 → 结束。
超过 `Check Interval` 秒检查一次（不需要玩家做任何操作）。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Requirements | 是 | 空 | 每个元素：`Role Tag` + `Required Tags`（该身份必须有的装备 Tag 列表） |
| Check Interval | 否 | `0.5` | 轮询间隔（秒），一般不用改 |

**常见配错**：

- `Required Tags` 里的 Tag 和物品那边贴的 Tag 不一致。
- 配了某个身份，但场上没有这个身份的人 → 永远不满足 → 卡死。
- `Requirements` 为空 → 任务立刻结束（警告）。

**示例**：06 步三人领装；22 步装备清点（同一类型，只改 `Requirements`）。

### 7.7 EquipmentConfirm —— 选装确认 + 锁定装备

**一句话**：展示每个人当前拿了什么装备，等每个人点“确认装备”后**锁定**（贴上锁定 Tag，物品侧禁止再换装）。

**什么时候结束**：所有**在场身份**都点过确认 → 给每个 Pawn 贴上锁定 Tag → 结束。

> ⚠️ **v1.1 起，这个任务不再核对、不再扣分**。核对和扣分请使用独立的 `EquipmentAudit` 任务（见下一节）。
> 一般配法：一个步骤里只放 `EquipmentConfirm`；下一步再放 `EquipmentAudit`。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Equipment Tag Pool | 是 | 空 | 哪些 Tag 算“装备”。**不在池子里的 Pawn Tag 会被忽略**（比如身份 Tag），面板上不显示 |
| Equipment Locked Tag | 否 | `EquipmentLocked` | 确认后给 Pawn 贴上的锁定 Tag，物品侧检测到它应禁止换装 |
| Confirm Button Id | 否 | `Confirm` | 一般不用改 |
| Confirm Button Text | 是 | 空 | 按钮文字 |
| Panel Title / Content | 建议 | 见默认 | 面板文案 |
| Audience | 是 | `AllParticipants` | 发给所有人 |

**锁定机制**：

- 任务结束时，给每个**已确认**的玩家 Pawn 贴一个 Tag（默认 `EquipmentLocked`）。
- 物品/交互系统检测到 Pawn 有这个 Tag 时，应拒绝拾取/丢弃装备。
- 任务系统只负责贴 Tag，**真的禁止换装由物品侧做**。

**常见配错**：

- `Equipment Tag Pool` 忘了包含某个装备 Tag → 玩家明明拿了，面板显示“未领取”。
- 把 `Role_1` 这类身份 Tag 也放进池子 → 面板上会把身份当成“装备”显示。
- 想让“确认后立即扣分” → 这个任务不扣分，请改用 `EquipmentAudit`。

**示例**：05 步。

### 7.8 EquipmentAudit —— 装备核对 + 扣分（v1.1 新增）

**一句话**：按标准表核对该身份当前身上的装备，**少拿 / 多拿各扣一次分**，核对完立即结束。

**什么时候结束**：所有在场身份核对完毕 → 立即结束（不等任何按钮）。

> 用法：一般紧跟 `EquipmentConfirm` 之后。
> 如果某一步只想核对、不想锁装备，也可以单独用 `EquipmentAudit`。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Standard Equipment | 是 | 空 | 每个元素：`Role Tag` + `Required Tags`（该身份的标准装备） |
| Equipment Tag Pool | 是 | 空 | 哪些 Tag 算“装备”。不在池子里的 Pawn Tag 会被忽略 |
| Missing Equipment Error Code | 是 | `EquipmentMissing` | 少拿装备的错误码（第 9 章配分） |
| Wrong Equipment Error Code | 是 | `EquipmentWrong` | 多拿/拿错的错误码 |

**核对规则**：

- 少拿：标准里有、玩家 Pawn 上没有 → `Missing Equipment Error Code`。
- 多拿/拿错：玩家身上有、但不在该身份标准里 → `Wrong Equipment Error Code`。
- 每个身份各判一次；缺席身份不判、不扣分。
- 同一身份“少 2 件”只扣 1 次；同时少又错，会各扣 1 次（共 2 次）。

**常见配错**：

- `Standard Equipment` 为空 → 任务直接结束，不扣任何分。
- `Equipment Tag Pool` 漏了某个装备 Tag → 那个装备会被当成“不存在”，可能误报“少拿”。
- 把身份 Tag（`Role_1` 等）放进池子 → 会被当成“多拿的装备”扣分。

**示例**：22 步装备清点。

### 7.9 TagMonitor —— 监听 Pawn 上的标签（v1.1 新增）

**一句话**：低频轮询玩家 Pawn 上的 Tag，**指定身份贴上了指定 Tag 就结束**。典型场景：执法记录仪开启、戴上某件装备等。

**什么时候结束**：按 `bRequireAllRoles` 判定：

- `bRequireAllRoles = true`（默认）：`MonitoredRoles` 里**每个身份**都至少贴上了它对应的**任意一个** Tag。
- `bRequireAllRoles = false`：`MonitoredRoles` 里**任意一个身份**贴上任意一个 Tag 即可。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Monitored Roles | 是 | 空 | TMap：`Role Tag → 监听的 Tag 列表`。任一 Tag 命中即算该身份满足 |
| bRequireAllRoles | 是 | 勾选 | 勾选=所有身份都满足才算过；取消=任意一个满足即过 |
| Check Interval | 否 | `0.5` | 轮询间隔（秒），一般不用改 |

**典型用法：执法记录仪**

物品侧在玩家开启执法记录仪时给 Pawn 贴 `BodyCam_Recording` Tag，关闭时移除。
配表：

```
MonitoredRoles = { Role_1 → [BodyCam_Recording] }
bRequireAllRoles = true
```

**常见配错**：

- 物品侧没贴对应 Tag → 任务永远不结束。
- `Monitored Roles` 为空 → 任务立刻结束（警告）。
- 同时监听多个 Tag 但只想要其中一个 → 把多个 Tag 都填到该身份的数组里即可（是“或”的关系）。

**示例**：在脚本中“开启执法记录仪”步骤使用。

### 7.10 StayInArea —— 警戒待命（必须留在区域内）

**一句话**：玩家必须待在指定碰撞盒里，离开就提示 + 扣一次分，回来恢复。

**什么时候结束**：

- `Required Compliant Duration > 0`：**所有人**持续合规达到 N 秒 → 自动结束。
- `Required Compliant Duration = 0`（默认）：**永远不自己结束**，必须由外部调用 `FinishMonitoring`（比如“支援到场”事件）。⚠️

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Zone Actor Tag | 是 | `SafeArea` | 区域碰撞盒 Tag |
| Require Inside Zone | 是 | 勾选 | 勾选=必须留在里面；取消=必须待在外面 |
| Warning Panel Type | 否 | `ScenePrompt` | 违规提示面板皮肤 |
| Warning Title | 建议 | 空 | 违规标题 |
| Warning Content | 建议 | 空 | 违规正文 |
| Violation Error Code | 是 | `LeaveArea` | 上报给评分的错误码 |
| Required Compliant Duration | 是 | `0` | ⚠️ 0 = 不自动结束 |
| Panel Title / Content | 建议 | 见默认 | 正常状态面板 |
| Audience | 是 | `AllParticipants` | 发给谁 |

**违规规则**：

- 同一玩家在整个任务里**只扣一次分**，反复进出不重复扣。
- 违规时该玩家看到警告面板，回到区域后恢复成正常面板。

**常见配错**：

- `Required Compliant Duration` 留 0，又没人调用外部结束 → 永久卡住。
- `Zone Actor Tag` 场景里没有 → 任务开始时找不到区域，不会自动判违规，但流程仍然不会自己结束。
- 区域碰撞盒只覆盖了一部分，玩家站在边缘被误判。

**示例**：07 步、16 步（如果脚本里是“等支援到场”就保持 0，由事件结束；如果是“坚持 30 秒”就填 30）。

### 7.11 KeepSafeDistance —— 保持安全距离

**一句话**：玩家必须待在嫌疑人碰撞盒**外面**；靠近就提示 + 扣一次分。

**什么时候结束**：与 `StayInArea` 相同，默认不自动结束；由外部事件结束或填持续时长。

**字段**（大部分继承自 `StayInArea` 的父类）：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Zone Actor Tag | 是 | `Suspect` | 嫌疑人 Pawn 的 Tag（`ASuspectPawn` 上自己打） |
| Require Inside Zone | 是 | **不勾选** | 这个任务必须是“待在外面” |
| Warning Title / Content | 建议 | “距离过近”等 | 靠近时的提示 |
| Violation Error Code | 是 | `SafeDistanceViolation` | 评分错误码 |
| Required Compliant Duration | 是 | `0` | ⚠️ 0 = 不自动结束 |

> **安全距离不是填数字**，而是调整场景里嫌疑人 Pawn 的 `TriggerBox` 大小。

**常见配错**：

- 嫌疑人 Pawn 上没打 `Suspect` Tag。
- 把 `Require Inside Zone` 勾上了 → 逻辑反转成“必须贴着嫌疑人”。
- 嫌疑人身上的碰撞盒太小，玩家贴着脸才报警。

**示例**：09 步、12 步。

### 7.13 VoiceRecognitionWait —— 等语音关键词（总时长制，v1.1 重构）

**一句话**：显示参考话术，等外部语音识别系统把识别文本传进来；**在总时长内**命中关键词就成功，**超时未命中就扣分并结束**。

**什么时候结束**：

- 关键词命中 → 立即结束（成功，不扣分）。
- `Total Duration` 时间到 → 上报 `Timeout Error Code` 扣分后结束（流程继续走）。
- **没配关键词** → 任何识别结果都算通过。

> ⚠️ **v1.1 重构**：旧的“单轮超时 + 重试次数”机制已废弃，改为“总时长内不限尝试次数”。识别失败不再重置计时器。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Speaker Role Tag | 是 | `Role_1` | 谁说话。别人说的识别结果会被忽略 |
| Speaker Pose Tag | 否 | 空 | 预留的姿态 Tag，目前不参与判定 |
| Subtitle Text | 建议 | 空 | 参考话术（显示给玩家） |
| Required Key Words | 是 | 空 | 每个词：Keyword / bRequired / Synonyms（分号分隔） |
| Keyword Match Policy | 是 | `All` | All=所有必填词都命中；Any=任意一个；Ratio=按比例 |
| Required Ratio | 条件 | `0.6` | 仅 Ratio 用（0.6 = 60%） |
| **Total Duration** | 是 | `30` | 总时长（秒）。期间可无限次尝试。**0 = 不限时**，慎用 |
| **Custom Event Id** | 是 | `VoiceRecognition` | 自定义事件 ID，外部语音识别上报时必须用同一个 ID |
| **Timeout Error Code** | 建议 | 空 | 超时时上报的错误码。空 = 超时不扣分（不推荐） |

**关键词规则细节**：

- 匹配是“包含”关系，且忽略大小写：识别文本里包含关键词就算命中。
- `Synonyms` 用英文分号分隔，例如 `驻地;管控区域;警戒区`。
- `bRequired = false` 的词只参与 Any/Ratio 的“命中统计”，不影响 All 的必过项。

**外部接入（程序员对接，策划只需了解）**：

语音识别在玩家本机（VR 头显 / PC 麦克风）运行，识别出文字后通过 PlayerState 上的通道组件上报：

```
Channel->SubmitCustomEvent("VoiceRecognition", 识别文本)
```

任务只接收 `Custom Event Id` 匹配的上报，其它事件会被忽略。

**常见配错**：

- 关键词写得太长/太书面 → 语音系统识别不出来，直到超时。
- `Speaker Role Tag` 和实际说话的人身份不一致 → 识别结果被忽略。
- `Total Duration = 0` → 任务永远不结束，等同于“无限期等待”，慎重使用。
- `Timeout Error Code` 留空 → 超时只是打日志，不扣分，玩家站着不动也能过。
- `Custom Event Id` 改了但外部代码没同步 → 永远收不到识别结果。

**示例**：11、14、15、20 步。

### 7.14 NPCBehavior —— NPC 行为序列

**一句话**：让 NPC 按列表顺序做一串动作：走位 → 等待 → 播动画 → 说话 → 面向 → 销毁。

**什么时候结束**：`Behavior Sequence` 全部节点执行完。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| NPC Class | Spawn 模式必填 | 空 | 要生成的 NPC 类 |
| Use Existing NPC | 否 | 不勾 | 勾上=不生成，接管场景里已有的 NPC |
| Existing NPC Tag | 条件 | 空 | 接管模式下按这个 Tag 找 NPC |
| NPC Count | 否 | `1` | 生成几个 |
| Spawn Point Tag | 否 | 空 | 生成点 Actor 的 Tag（优先） |
| Spawn Location / Rotation | 否 | 0 | 没有 Spawn Point Tag 时用坐标 |
| Behavior Sequence | 是 | 空 | 节点列表，见下 |
| Auto Destroy On End | 否 | 不勾 | 任务结束时是否销毁生成的 NPC |

**行为节点（Behavior Sequence 的一个元素）**：

| 字段 | 说明 |
|---|---|
| Node Type | `MoveTo` / `Wait` / `PlayAnim` / `PlayAudio` / `LookAt` / `SetAIState` / `Destroy` |
| Target Location | MoveTo 的目标坐标（`Target Location Tag` 为空时用） |
| Target Location Tag | MoveTo 目标 Actor 的 Tag（优先于坐标） |
| Acceptance Radius | MoveTo 接受半径（厘米） |
| Wait Duration | Wait 节点等几秒 |
| Anim To Play | PlayAnim 节点播的动画 |
| Audio To Play | PlayAudio 节点播的声音 |
| Look At Target Tag | LookAt 节点看向哪个 Tag |
| AI State Name | SetAIState 节点（目前只打日志，不做实际行为） |
| Delay Before Next | 本节点做完后，等几秒再执行下一个 |

**行为细节**：

- `MoveTo`：如果 NPC 没有 AI 控制器 / 导航网格，会记录警告并**直接跳到下一节点**（不会卡住）。
- 多个 NPC 时，**全部到达后才进入下一节点**。
- `PlayAudio`：只等第一个有音频组件的 NPC 播完。
- `SetAIState`：目前是占位实现，只打日志。
- `Destroy`：销毁当前受控 NPC，然后继续下一节点。

**常见配错**：

- 场景没铺 NavMesh → NPC 不走，直接跳过移动节点。
- Spawn 模式下 `NPC Class` 没填 → 任务立刻结束。
- 期望 NPC 说话但 PlayAudio 节点没填音频 → 直接跳过该节点。

**示例**：08 步支援警察走位 + 说话；17 步嫌疑人动作。

### 7.15 MediaPlayback —— 顺序播放音频/动画序列（v1.1 新增，合并 PlayAnim + PlayAudio）

**一句话**：按 `Playlist` 数组顺序，依次播放每一条；每条可以同时包含音频、动画，或两者之一；支持播放前后延迟、指定播放位置。

**什么时候结束**：`Playlist` 里所有条目播放完成（含 Delay After）→ 结束。

> ⚠️ **v1.1 起，`PlayAnim` 和 `PlayAudio` 不再单独存在**，统一使用 `MediaPlayback`。原本只播动画或只播音频的需求，配置一条 `Playlist` 即可。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Playlist | 是 | 空 | 播放列表，见下表 |

**Playlist 里每一条的字段（FMediaPlaybackItem）**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Sound | 条件 | 空 | 要播的音频资产（可选） |
| Anim Sequence | 条件 | 空 | 要播的动画资产（可选）。Sound 和 Anim 至少填一个 |
| Location Type | 是 | `AtLocation` | `AtLocation` = 在世界坐标播放；`OnPawn` = 跟着某个 Pawn |
| Location | 条件 | 0 | LocationType = AtLocation 时的世界坐标 |
| Target Role Tag | 条件 | 空 | LocationType = OnPawn 时，按身份找目标 Pawn |
| Target Pawn Ref | 条件 | 空 | LocationType = OnPawn 时，直接指定 Pawn（用于 NPC，优先级低于 Role Tag） |
| Delay Before | 否 | `0` | 这一条开始**之前**等几秒 |
| Delay After | 否 | `0` | 这一条播完**之后**等几秒再播下一条 |
| bWait Anim End | 是 | 勾选 | 勾选=等动画播完才算这条完成；取消=动画一开播就立即开始等下一条 |
| Loop Count | 是 | `1` | 动画循环次数。1 = 播一次；N = 播 N 次；**0 = 无限循环（慎用，会导致永不结束）** |

**行为细节**：

- 一条里同时有音频和动画 → 同时开始播放，**两者都完成**才进入下一条。
- 一条只有音频或只有动画 → 只等那一个完成。
- 某一条目标找不到 / 资产为空 → 跳过该条继续下一条（会打警告）。
- `AtLocation` 的音频播完会自动销毁音频组件。
- 动画播在 Pawn 身上时，需要该 Pawn 有 SkeletalMesh；没有则该条被跳过。

**常见配错**：

- `Loop Count = 0` 且 `bWait Anim End` 勾选 → 动画无限循环，任务永远不结束。⚠️
- 想“语音一响玩家就能听到”，结果 `Location` 放在了另一个房间。
- 位置音用了相对坐标的思路 → UE 里全是世界坐标。
- `Playlist` 为空 → 任务立刻结束（警告）。

**示例**：08 步支援到场（NPC 走位 + 喊话）；17 步嫌疑人反应。

### 7.16 SearchInspection —— 搜身检查

**一句话**：按部位顺序检查，玩家碰到“当前部位”的碰撞盒就通过一个部位，全部部位完成结束。

**什么时候结束**：`Body Parts` 全部检查完。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Target Actor Tag | 是 | `Suspect` | 被搜身目标的 Tag（用于定位音效位置等） |
| Inspector Role Tags | 否 | 空 | 允许搜身的身份；空=所有 Pawn 都可以 |
| Body Parts | 是 | 空 | 每个部位：Part Name / Socket Name / Collision Box Tag |
| Highlight Color | 否 | 绿色 | 预留的高亮颜色（显示由框架/蓝图实现） |
| Part Complete Sound | 否 | 空 | 每检查完一个部位的音效 |
| All Complete Sound | 否 | 空 | 全部检查完的音效 |
| Search Result Text | 否 | 空 | 搜身结果文字（目前只进日志） |

**工作方式**：

1. 按 `Body Parts` 数组顺序，从第 0 个开始。
2. 玩家 Pawn 碰到 `Collision Box Tag` 对应的碰撞盒 → 该部位完成，进入下一个。
3. 如果某个部位没填 `Collision Box Tag` → **任何 Pawn 碰到任何转发过来的碰撞盒都算完成**（不推荐）。

**常见配错**：

- 部位碰撞盒 Tag 没在场景里打。
- `Body Parts` 为空 → 任务立刻结束。
- 想用“靠近身体部位自动识别” → 当前只支持碰撞盒。

**示例**：18 步。

### 7.17 EndTraining —— 结束训练

**一句话**：显示结束面板，两个按钮：返回课件列表 / 重新训练本课件。

**什么时候结束**：玩家点任意一个按钮后结束；不点就一直停在这一步。

**字段**：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| Panel Title / Content | 建议 | 见默认 | 结束文案 |
| Return To List Button Id | 否 | `ReturnToList` | 返回列表按钮 Id（框架按它判断） |
| Return To List Button Text | 建议 | “返回课件列表” | 按钮文字 |
| Restart Button Id | 否 | `Restart` | 重新训练按钮 Id |
| Restart Button Text | 建议 | “重新训练本课件” | 按钮文字 |
| Audience | 是 | `AllParticipants` | 发给所有人 |

**重要**：任务系统**只把选择结果抛给外层框架**（`OnTaskChoiceMade`），不负责真正切场景/重开。
所以：**点了按钮没反应 = 框架没接这个事件**，找程序，不是配表问题。

## 9. 评分配置

### 9.1 分数怎么算

- 每个身份初始 **100 分**（评分组件的 `Base Score`）。
- 每上报一次错误码，按该错误码的 `Penalty` 扣分。
- 最低 0 分，不会扣成负数。
- 同一身份可以多次扣分（`Violation Count` 记录次数，`Violated Error Codes` 去重记录触发过哪些错误码）。

### 9.2 在哪配规则

配在 **Step 的 `Score Rules`** 数组里：

| 字段 | 说明 |
|---|---|
| Error Code | 错误码，必须和任务里填的**完全一致** |
| Description | 中文说明（报表/调试用） |
| Penalty | 扣几分（正整数） |

> 查找顺序：先查“当前步骤”的规则，再查整张表的规则。
> 所以规则配在哪个步骤都能生效，但**建议配在会触发它的那个步骤**，便于阅读。

### 9.3 系统默认会产生的错误码

| 错误码 | 来自哪个任务 | 什么时候产生 |
|---|---|---|
| `LeaveArea` | `StayInArea` | 玩家离开警戒区域（每人每任务一次） |
| `SafeDistanceViolation` | `KeepSafeDistance` | 玩家进入安全距离（每人每任务一次） |
| `EquipmentMissing` | `EquipmentAudit` | 某身份少拿标准装备（任务结束核对时一次） |
| `EquipmentWrong` | `EquipmentAudit` | 某身份多拿/拿错装备（任务结束核对时一次） |
| *自定义* | `VoiceRecognitionWait` | 总时长内没说到关键词（由 `Timeout Error Code` 字段决定，默认空） |

> 只有上表前 4 个错误码是任务内置的固定默认值。
> `VoiceRecognitionWait` 的错误码由你在任务字段里配，**配了什么就是什么，留空则不扣分**。
> 任务里可以改错误码（`Violation Error Code` / `Missing Equipment Error Code` 等字段），改了以后记得在 `Score Rules` 里配同名规则。

### 9.4 漏配规则会怎样

- 不会崩溃。
- 该次上报按 **0 分**处理，日志出现：
  ```
  [Score] Error code xxx has no score rule in current task, recorded with 0 penalty
  ```
- 看到这条日志，说明你的配表漏了规则或错误码写错了。

### 9.5 推荐配法（示例）

| Error Code | Description | Penalty |
|---|---|---|
| `LeaveArea` | 擅自离开警戒区域 | 10 |
| `SafeDistanceViolation` | 与嫌疑人距离过近 | 15 |
| `EquipmentMissing` | 未按要求携带装备 | 10 |
| `EquipmentWrong` | 携带非标准装备 | 5 |
| `VoiceTimeout` | 喊话超时未达要求 | 10 |

> `VoiceTimeout` 是自定义示例，你需要在每个 `VoiceRecognitionWait` 任务的 `Timeout Error Code` 字段填同一个值。

## 10. 十个最容易配错的地方（必看）

> 下面每一条都可以先用第 11 章的 `Task.Validate` 自动查一遍，能省掉大半人工排查。

### ① 任务不往下走了，日志只有“Step 开始”

按顺序检查这 4 项：

1. **这个步骤里的面板任务有没有填关闭/确认相关字段？**
   - `UIPanelDisplay` 的 `Auto Close Delay` 是 0 → 永远不结束。
   - `WaitForConfirm` 的 `Confirm Button Text` 为空 → 没按钮可点。
2. **`StayInArea` / `KeepSafeDistance` 的 `Required Compliant Duration` 是不是 0？**
   - 0 = 必须由外部结束。没人结束就永远卡着。
3. **站位类任务的 `Role Tag` 是不是都有人？**
   - 少一个人，就少一个“到位”。
4. **`EquipmentInteract` 配的身份是不是都在场？**
   - 缺席身份永远拿不齐装备。

### ② 面板一闪而过 / 直接跳过

- `WaitForConfirm` 的 `Confirm Policy = SpecificRoles`，但 `Specific Role Tags` 是空的 → 立即满足。
- `MultiStationArrival` / `StationConfirm` 的 `Station Tag` 场景里找不到 → 任务直接结束。

### ③ 玩家点了按钮没反应

- 按钮不是任务自己的按钮（你加在了 `Panel Buttons` 里，但任务不处理它）。
- `Confirm Button Text` 没填，玩家点的是你额外加的装饰按钮。
- 面板已过期（另一个面板覆盖了它），点击被丢弃。

### ④ 两个面板互相覆盖

- 同一个步骤里放了两个面板任务。**一个步骤只放一个面板任务**，其余拆到下一步。

### ⑤ 玩家永远选不到身份

- 配了 3 个身份但只有 2 个玩家，且 `Require All Participants` 勾着 → 等第 3 个玩家。
- 身份 `Role Tag` 前后不一致（`Role1` vs `Role_1`）。

### ⑥ 装备明明拿了，面板显示“未领取”

- `Equipment Tag Pool` 里没包含该装备 Tag。
- 物品那边没往 Pawn 上贴 Tag（找程序确认）。

### ⑦ 安全距离不对

- 安全距离不是配表数字，是嫌疑人 Pawn 上 `TriggerBox` 的尺寸。
- 嫌疑人没打 `Suspect` Tag，或任务的 `Zone Actor Tag` 写错。

### ⑧ 语音任务一直超时

- 关键词太书面 / 太长，语音系统识别不出来。
- `Speaker Role Tag` 写错，识别结果被忽略。
- `Custom Event Id` 改了但外部代码没同步 → 永远收不到识别结果。
- `Total Duration` 设得太短，玩家还没来得及说完就超时。
- 外部根本没接入语音识别 → 每个语音任务都会超时；如果 `Timeout Error Code` 有配，会按人数扣分。

### ⑨ NPC 不走

- 场景没铺 NavMesh，或 NPC 没有 AI 控制器。
- 没有 AI 时任务会跳过移动节点（不会卡住），但表现就是“没走”。

### ⑩ 结束页按钮点了没反应

- `EndTraining` 只把 `ButtonId` 抛给框架（`OnTaskChoiceMade`）。
- 框架没绑定这个事件 → 找程序。

## 11. 调试工具（配表出问题先跑这个）

配表配错时，最常见的表现是「**流程卡住，日志里什么错都没有**」。
系统内置了一个调试工具，专门解决这个问题。全部功能都在**控制台**里用，不需要改代码、不需要重启工程。

> 这个工具只在**编辑器 / 开发版**里存在，正式打包发布（Shipping）不会带上，对成品没有任何影响。

### 11.0 第一步永远是：跑一次自检

1. 启动 PIE（或单机运行），确保任务配表已经加载。
2. 按键盘 **`~`**（Esc 下面那个键）打开控制台。
3. 输入：

```
Task.Validate
```

4. 回车。控制台会逐条列出问题，最后一行是汇总。

输出长这样：

```
===== 配表校验：DA_持械对峙 =====
[错误] Step[04] Step_04 / MultipleTask_WaitForConfirm | ConfirmButtonText 为空，不会生成确认按钮，永远无法完成
[警告] Step[06] Step_06 / MultipleTask_EquipmentInteract | 场景中找不到带 Tag Station_Equip 的站位碰撞盒
[提示] Step[03] Step_03 / MultipleTask_RoleSelect | Roles 少于 3 个，标准流程需要 3 名参训玩家各选一个身份
汇总：错误 1，警告 2，提示 1
```

**三条级别怎么理解：**

| 级别 | 意思 | 要不要处理 |
|---|---|---|
| `[错误]` | 一定会导致流程卡死 / 跳过 / 无法完成 | **必须改**，否则跑不通 |
| `[警告]` | 大概率配错了，但流程还能走 | 强烈建议改 |
| `[提示]` | 建议项 | 看情况，可以忽略 |

> 如果控制台提示 `没有可校验的配表`，说明任务还没开始。先让游戏跑到任务启动，或者用第 11.3 节的指定路径方式校验。

### 11.1 全部命令一览

打开控制台输入 **`Task.Help`**，会打印下面这张表。

| 命令 | 怎么用 | 干什么 |
|---|---|---|
| `Task.Help` | `Task.Help` | 列出所有命令 |
| `Task.Validate` | `Task.Validate` 或 `Task.Validate /Game/路径/DA_XXX` | 配表自检（见上一节） |
| `Task.Dump` | `Task.Dump` | 打印整张配表的步骤和任务清单 |
| `Task.Skip` | `Task.Skip 8` | 直接跳到指定步骤（**从 0 开始数**，`Task.Skip 8` = 第 9 步） |
| `Task.Finish` | `Task.Finish All` / `Task.Finish MediaPlayback` | 结束当前步骤里活跃的任务 |
| `Task.Restart` | `Task.Restart` | 用当前配表重新开始整个训练 |
| `Task.Roles` | `Task.Roles` | 查看谁是几号身份、谁还没选 |
| `Task.Panels` | `Task.Panels` | 查看每个玩家当前收到的是什么面板 |
| `Task.Scores` | `Task.Scores` | 查看当前每个人的分数和扣分记录 |
| `Task.Debug` | `Task.Debug 1` / `Task.Debug 0` | 打开 / 关闭场景可视化 |

> 输入命令时**不区分大小写**，`task.validate` 和 `Task.Validate` 一样。

### 11.2 `Task.Dump` —— 确认配表到底长什么样

最常用的第二个命令。它会把你配的表原样打印出来，用来确认「我是不是漏加了某一步」「这个任务到底是不是我选的那个类型」。

```
Task.Dump
```

```
===== 持械对峙（共 23 步）=====
[00] Step_00  事件接收与初步判断
      TaskName  <MultipleTask_UIPanelDisplay>
[01] Step_01  现场分工
      TaskName  <MultipleTask_RoleSelect>
[02] Step_02  领装
      TaskName  <MultipleTask_EquipmentConfirm>
      -5  EquipmentMissing  (少拿装备)
```

看懂三件事：

- 方括号里是**步骤序号**，从 0 开始。
- `<...>` 里是**任务类名**，对应第 7 章的类型说明。
- 缩进的 `-5 EquipmentMissing` 是**这一步的评分规则**。

如果打印出来的类名和你以为的不一样，说明加任务时选错类型了——这是很常见的配错。

### 11.3 `Task.Validate` 指定路径校验（不开游戏也能查）

不想进 PIE，只想检查一张配表？把资产路径直接写上。

1. 在 Content Browser 里右键配表资产 → **Copy Reference**。
2. 控制台输入：

```
Task.Validate /Game/TaskSystem/DA_持械对峙.DA_持械对峙
```

> 路径格式必须是 `/Game/...` 开头、带 `.资产名` 结尾。
> 复制出来的引用如果带引号，把引号去掉再粘。

这种方式**不需要任务正在运行**，但「场景里有没有这个 Tag」这类检查需要当前关卡，所以建议还是进 PIE 后再跑一次。

### 11.4 卡住的时候怎么用 `Task.Skip` / `Task.Finish`

**场景：** 走到第 9 步不动了，你想知道后面配得对不对。

```
Task.Skip 8
```

直接跳到第 9 步（**序号从 0 开始**：第 1 步是 `Task.Skip 0`，第 9 步是 `Task.Skip 8`）。

**场景：** 某个「等外部事件」的任务永远等不到（比如警戒待命），你想让它先过去。

```
Task.Finish StayInArea
```

按**类名的一部分**匹配，不用写完整类名。也可以一次结束当前步骤的全部任务：

```
Task.Finish All
```

匹配不到时会提示 `没有匹配的活跃任务`，此时用 `Task.Dump` 看看当前到底有哪些任务。

> `Task.Skip` 和 `Task.Finish` 只影响当前这一局，不会改你的配表。刷新 PIE 就恢复原样。

### 11.5 `Task.Restart` —— 反复调试不用重开 PIE

改完配表之后，不必关掉 PIE 再重来：

```
Task.Restart
```

会用**当前加载的同一张配表**重新从头跑。适合反复验证某一个改动点。

> 如果改的是资产里的字段，记得先保存资产（Ctrl+S），`Task.Restart` 读的是内存里的资产内容。

### 11.6 `Task.Roles` —— 谁是谁

怀疑「身份分配」出问题时用：

```
Task.Roles
```

```
===== 参训玩家 3 人 =====
  PlayerA → Role_1
  PlayerB → Role_2
  PlayerC → <未分配>
  已占用身份：Role_1, Role_2
```

- `<未分配>` 的玩家就是**导致「所有人选完身份」这一步过不去**的元凶。
- 如果这里显示 0 人，说明**参训玩家根本没注册**——这是程序侧的事（见文末「给程序的交接信息」），不是你配表的问题。

### 11.7 `Task.Panels` —— 面板到底发了没

怀疑「面板没弹出来 / 弹出的是上一个」时用：

```
Task.Panels
```

```
===== 面板状态（3 人）=====
  PlayerA：可见=是  PanelId=MultipleTask_RoleSelect_0  标题=请选择你的身份
  PlayerB：可见=是  PanelId=MultipleTask_RoleSelect_0  标题=请选择你的身份
  PlayerC：没有面板通道组件
```

三种典型结论：

| 看到什么 | 说明 |
|---|---|
| `可见=否` | 这一步没有面板任务，或者面板已结束 |
| `标题=` 是别的步骤的 | 面板被更早的任务占着，`bHidePanelOnEnd` 没生效或任务没结束 |
| `没有面板通道组件` | 该玩家没被注册为参训玩家（程序侧） |

### 11.8 `Task.Scores` —— 分数对不对

验证评分规则有没有生效：

```
Task.Scores
```

```
===== 评分板（3 条）=====
  Role_1：得分 95，扣分 5，异常 1 次，错误码：LeaveArea
  Role_2：得分 100，扣分 0，异常 0 次
  Role_3：得分 100，扣分 0，异常 0 次
```

如果**做了违规动作却没有记录**，检查这个错误码在对应步骤的 `Score Rules` 里有没有同名规则（见 9.4）。

### 11.9 `Task.Debug 1` —— 把场景里的 Tag 全画出来

这是最直观的功能。输入：

```
Task.Debug 1
```

游戏画面上会多出：

| 显示 | 含义 |
|---|---|
| 绿色文字 | Actor 身上的 Tag（每个 Tag 一行，浮在物体上方） |
| 绿色线框 | 当前任务正在用的**区域**（警戒区 / 安全距离区） |
| 青色线框 | 当前任务正在用的**站位碰撞盒** |
| 黄色线框 | 当前任务要找的**搜身目标** |
| 红色 `MISSING TAG: xxx` | 配表里写了这个 Tag，但**场景里找不到** |
| 左上角文字 | 当前第几步、有哪些任务在跑、谁是谁的身份 |

**最重要的用法：看到红色 `MISSING TAG`，就等于直接告诉你「配表的 Tag 和场景对不上」。**

关闭：

```
Task.Debug 0
```

> 这个开关默认是关的。它只在你自己的开发机上显示，不影响别人。

### 11.10 一个完整的排错流程

照着这个顺序走，99% 的卡死都能定位：

```
第 1 步   Task.Validate          → 有没有 [错误]？有就直接改
第 2 步   Task.Dump              → 当前步骤的任务类型选对了吗？
第 3 步   Task.Roles             → 三个人的身份都分配了吗？
第 4 步   Task.Panels            → 这一步的面板真的下发了吗？
第 5 步   Task.Debug 1           → 场景里有没有红色 MISSING TAG？
第 6 步   Task.Finish All        → 能过去吗？能过去说明就是这一步的任务没被满足
```

### 11.11 自检能查出哪些问题（对照表）

`Task.Validate` 会覆盖下面这些，**带 ⚠ 的都是会让流程卡死的高危项**：

| 任务类型 | 检查内容 |
|---|---|
| 所有任务 | 步骤为空、步骤 ID 重复、步骤里没有任务、空任务项 |
| ⚠ `UIPanelDisplay` | `Auto Close Delay` 是不是 0（面板永不关闭） |
| ⚠ `WaitForConfirm` | `Confirm Button Text` 有没有填；指定身份策略是否忘了填身份 |
| `RoleSelect` | `Roles` 为空、身份 Tag 重复、身份数量少于 3 |
| ⚠ `MultiStationArrival` / `StationConfirm` | 要求表为空、身份/站位 Tag 为空、站位在场景里找不到 |
| `GuideToLocation` | 站位 Tag 为空或找不到、身份 Tag 为空、开了引导但没配标志类 |
| `EquipmentInteract` | 要求表为空、某身份装备清单为空、轮询间隔过小 |
| `EquipmentConfirm` | 装备 Tag 池为空、锁定 Tag 为空、按钮文字为空 |
| `EquipmentAudit` | 标准装备为空、装备 Tag 池为空、某身份清单为空、错误码为空 |
| `TagMonitor` | 监听表为空、某身份 Tag 列表为空、轮询间隔过小 |
| ⚠ `StayInArea` / `KeepSafeDistance` | 区域 Tag 为空（会直接跳过）或找不到；持续时长 ≤ 0；违规错误码为空 |
| `SearchInspection` | 部位列表为空、部位碰撞盒 Tag 为空、目标 Tag 找不到 |
| `NPCBehavior` | NPC 类/接管 Tag 没填、数量 ≤ 0、行为序列为空、各节点必要字段缺失 |
| `MediaPlayback` | 播放列表为空、某条 Sound/Anim 都为空、LoopCount 为负 |
| `VoiceRecognitionWait` | 关键词列表为空、关键词为空、比例模式比例 ≤ 0、Total Duration ≤ 0、Custom Event Id 为空 |
| `EndTraining` | 两个按钮文字都为空 |
| 评分 | 用到的错误码，全表 `Score Rules` 里找不到同名规则 |

### 11.12 常见疑问

**Q：控制台打不开？**
A：先用鼠标点一下 PIE 窗口让它获得焦点，再按 `~`（Esc 下面那个键）。有些键盘布局需要按 `Ctrl + ~`，也可以直接在编辑器菜单 `Window → Output Log` 底部的命令行输入。

**Q：提示「找不到 Sequencer」？**
A：说明任务驱动器还没创建（任务还没开始）。等进入训练场景后再执行。

**Q：`Task.Validate` 报了一堆 [提示]，需要全改吗？**
A：不用。只处理 `[错误]`，`[警告]` 挑和自己场景相关的看。`[提示]` 只是建议。

**Q：这些命令会把配表改坏吗？**
A：不会。所有命令都是只读查看，或者只影响当前这一局运行状态；配表资产一个字都不会动。

**Q：正式版能用吗？**
A：不能，也不应该。工具在 Shipping 包里不存在。

## 12. 交付前检查清单

配完一份 23 步，请逐项打勾：

**配表结构**

- [ ] `Steps` 数量 = 23（或与脚本一致）
- [ ] 每个 `Step Id` 不重复
- [ ] 每个 `Step Title` 是中文、能看懂
- [ ] 每一步的 `Parallel Tasks` 至少 1 个
- [ ] 同一步骤里没有两个“面板任务”
- [ ] 所有 `UIPanelDisplay` 的 `Auto Close Delay` > 0，或已确认由外部结束
- [ ] 所有 `WaitForConfirm` 都填了 `Confirm Button Text`
- [ ] 所有 `StayInArea` / `KeepSafeDistance` 的 `Required Compliant Duration` > 0，或已确认有外部结束事件
- [ ] 所有 `MediaPlayback` 的 `Loop Count` 不是 0（除非就是要无限循环）
- [ ] 所有 `VoiceRecognitionWait` 的 `Total Duration` > 0 且 `Timeout Error Code` 已填
- [ ] 所有 `VoiceRecognitionWait` 的 `Custom Event Id` 与外部代码约定一致
- [ ] `EquipmentAudit` 的 `Standard Equipment` 与各身份 `Equipment Tag Pool` 一致
- [ ] `RoleSelect` 的 `Roles` 数量 ≥ 参训人数

**身份与 Tag 一致性**

- [ ] 所有任务里的身份 Tag 都来自同一套（`Role_1/2/3`）
- [ ] 场景 Tag 清单与实际场景一致（建议附一张表）
- [ ] 所有 `Station Tag` 在场景里真实存在
- [ ] 嫌疑人 Pawn 已打 `Suspect` Tag，碰撞盒尺寸 = 期望安全距离
- [ ] 警戒区碰撞盒已打 `SafeArea` Tag
- [ ] 装备 Tag 与物品侧约定一致，且已全部加入 `Equipment Tag Pool`

**评分**

- [ ] 所有用到的错误码都在某个 Step 的 `Score Rules` 里有同名规则
- [ ] 扣分值符合设计预期（每项 ≤ 100 总和合理）
- [ ] 确认 `Base Score` 是 100（除非设计另有要求）

**联调**

- [ ] 单人 PIE 能从头走到尾（或知道哪几步需要多人）
- [ ] 三人联机能完整走完 23 步
- [ ] Output Log 中无 `has no score rule` 警告
- [ ] Output Log 中无 `not found` 类警告（Tag 找不到）

## 13. 术语表

| 名词 | 意思 |
|---|---|
| DataAsset / 配表 | 你在 Content Browser 里建的那个 `PrimaryTaskDataAsset` 资产 |
| Step / 步骤 | 配表里的一行，按顺序执行 |
| Task / 任务项 | 步骤里装的一个具体任务 |
| Parallel Tasks / 并行任务 | 同一个步骤里同时执行的任务列表 |
| Role / 身份 | `Role_1` / `Role_2` / `Role_3`，由 04 步分配 |
| Participant / 参训玩家 | 进场时注册过的玩家；只有他们收面板、参与“全员”判定 |
| Tag / 标签 | 挂在 Actor 上的字符串标记，配表用 Tag 找物体 |
| TriggerVolume / 碰撞盒 | 场景里用来判断“人有没有进去”的盒子 |
| Overlap / 重叠 | 玩家进入/离开碰撞盒的事件 |
| Panel / 面板 | 发给玩家的 UI 数据；显示方式由外层框架决定 |
| Audience / 受众 | 面板发给谁：所有参训玩家 / 指定身份 |
| Confirm Policy / 确认策略 | 谁点了才算完成 |
| Error Code / 错误码 | 评分用的字符串标识，如 `LeaveArea` |
| Penalty / 扣分 | 每个错误码扣多少分 |
| Sequencer / 任务驱动器 | 挂在 GameState 上、负责按步骤跑任务的组件（程序侧） |
| Panel Channel / 面板通道 | 挂在 PlayerState 上、负责把面板发给玩家并收按钮的组件（程序侧） |

## 附：给程序的交接信息（策划可忽略）

配表以外的部分由程序完成：

- 在玩家进场时调用 `UTaskSequencerComponent::RegisterParticipant(PC)`；离开时 `UnregisterParticipant`。
- 在合适时机调用 `LoadAndStartTask(DataAsset)`。
- 关卡 TriggerVolume 的 Overlap 事件转发到 `ForwardOverlapBegin` / `ForwardOverlapEnd`。
- 框架 UI 读取 `UTaskPanelChannelComponent::GetPanel()` 并绑定 `OnPanelStateChanged` 显示面板；按钮点击调用 `SubmitPanelButton(ButtonId)`。
- 外部事件结束区域监控：`FinishActiveTasksByClass(UMultipleTask_StayInArea::StaticClass())` 或对实例调用 `FinishMonitoring()`。
- 框架绑定 `OnTaskChoiceMade` 处理结束页的“返回列表/重新训练”。
- **语音识别结果**：客户端拿到识别文本后，通过 PlayerState 上的 `UTaskPanelChannelComponent::SubmitCustomEvent(EventId, Text)` 上报；EventId 默认 `VoiceRecognition`，必须与配表里的 `Custom Event Id` 一致。
- 物品侧在装备被确认锁定后，遇到 `EquipmentLocked` Tag 应禁止换装。
- 评分板读取 `UScoreComponent::GetAllScores()`，绑定 `OnScoreBoardChanged` 刷新。
