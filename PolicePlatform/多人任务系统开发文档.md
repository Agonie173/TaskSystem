## 1. 这份系统是干什么的

一句话：

> **按配表顺序执行训练步骤。每一步可以包含多个并行任务；所有任务完成后自动进入下一步。**

它只做三件事：

1. **流程控制**：Step 0 → Step 1 → ... → Step N，全部完成发 `OnAllStepsCompleted`。
2. **条件判定**：人有没有到位、按钮有没有点、装备有没有拿、话有没有说对、有没有离开区域。
3. **数据下发**：把面板数据写到玩家身上，把违规换算成分数。

它**明确不做**：

- 不创建/显示任何 Widget（不判断 PC/VR，不做视口/3D 面板）。
- 不处理 VR 手柄射线、交互输入。
- 不做传送、生成装备、切场景、视频播放。
- 不引用外层框架的任何类。

## 2. 五条不可违反的硬约束

接手后改代码前，先把这五条抄在工位上。

### 2.1 任务系统不能 include 框架任何头文件

依赖方向是单向的：

```
框架  ──依赖──▶  任务系统
任务系统  ──✗──▶  框架
```

任务系统对外只暴露：

- `BlueprintCallable` 函数
- `BlueprintAssignable` 委托
- 继承点（`UMultipleTaskBase` / `UMultipleTask_PanelBase` / `UMultipleTask_ZoneMonitor`）

框架通过蓝图或 C++ 调用这些接口，任务系统不知道框架叫什么。

**检查方法**：在 `Source/PolicePlatform` 里全局搜索框架模块名或框架类名，应该 0 结果。

### 2.2 不写任何平台判断

不要出现 `IsVR()`, `bIsVR`, `Platform == ...`, `GetHMDDeviceType()` 之类。

UI 显示方式由外层框架决定：PC 端加视口，VR 端用 WidgetComponent，都不关任务系统的事。

### 2.3 所有状态权威在服务器

- 任务实例只存在于服务器（`DuplicateObject` 在 Sequencer 上）。
- 客户端只有：步骤索引、身份占用列表、面板数据、评分数据（都是复制属性）。
- 客户端任何“操作”都必须走 Server RPC（面板按钮已封装在 `UTaskPanelChannelComponent`）。

### 2.4 面板通道必须挂在 PlayerState 上

`UTaskPanelChannelComponent` 挂在 `APlayerState`，不要挪到 `AGameState`。

原因（踩过的坑）：

> `AGameState` 没有 Owner 链，在它上面定义的 Server RPC 会被 UE 静默丢弃。
> `APlayerState` 有 Owner（PlayerController），Server RPC 才能正常路由。

### 2.5 配表对象是模板，运行时必须 Duplicate

`UPrimaryTaskDataAsset::Steps[i].ParallelTasks[j]` 里的对象是**编辑期模板**，多个训练局共享。

`ExecuteStep` 里必须：

```cpp
UMultipleTaskBase* TaskInstance = DuplicateObject<UMultipleTaskBase>(SourceTask, this);
```

`this` 是 Sequencer（ActorComponent），这样 `TaskInstance->GetWorld()` 才能通过 Outer 链拿到 World。
**不要** `NewObject<UMultipleTaskBase>(GetTransientPackage())`，否则 `GetWorld()` 返回 null，定时器、音频、生成 Actor 全部静默失败。

## 3. 快速开始

### 3.1 编译

命令行（Windows PowerShell）：

```powershell
& "E:\Software\Epic Games\UE_5.3\Engine\Build\BatchFiles\Build.bat" `
  PolicePlatformEditor Win64 Development `
  -Project="e:\Peoject\Unreal Project\5_3\TaskSystem\PolicePlatform\PolicePlatform.uproject" `
  -WaitMutex -FromMsBuild
```

或者直接用 Rider / Visual Studio 编译 `PolicePlatformEditor` 目标。

### 3.2 模块依赖

`Source/PolicePlatform/PolicePlatform.Build.cs`：

```csharp
PublicDependencyModuleNames.AddRange(new string[] {
    "Core", "CoreUObject", "Engine", "InputCore", "AIModule", "UMG"
});
```

- `AIModule`：`NPCBehavior` 用 `AAIController` / MoveTo。
- `UMG`：目前没有直接使用 Widget，保留给以后扩展。

新增依赖时优先加 `PrivateDependencyModuleNames`，避免把依赖传染给框架。

### 3.3 让系统跑起来（最小接入）

**服务器/单机侧：**

1. 在 `AGameStateBase` 蓝图上添加组件 `TaskSequencerComponent`（必须手动加，系统没有自动创建它的入口）。
2. 评分组件可以手动加 `ScoreComponent`；也可以不加，第一次上报时 `FindOrCreateScoreComponent` 会自动创建。
3. 玩家进场时调用：

```cpp
UTaskSequencerComponent* Seq = GameState->FindComponentByClass<UTaskSequencerComponent>();
Seq->RegisterParticipant(PlayerController);
```

4. 开始训练：

```cpp
Seq->LoadAndStartTask(TaskDataAsset);
```

**客户端侧：**

1. 在 `APlayerState` 蓝图上添加 `TaskPanelChannelComponent`（不加也行，注册参与者时会自动创建）。
2. UI 蓝图里：

```
OnPanelStateChanged  → 读 GetPanel() 渲染
按钮点击            → SubmitPanelButton(ButtonId, RowIndex)
```

3. 客户端要显示“第几步”时，绑定 `OnStepStarted`（由复制属性 `CurrentStepIndex` 的 OnRep 广播）。

### 3.4 关卡 TriggerVolume 接入

任何期望被任务识别的碰撞盒，都要把 Overlap 事件转发给 Sequencer：

```text
TriggerVolume.OnComponentBeginOverlap
    → GameState → TaskSequencerComponent → ForwardOverlapBegin(OverlappedActor, OtherActor)

TriggerVolume.OnComponentEndOverlap
    → ForwardOverlapEnd(OverlappedActor, OtherActor)
```

建议写一个通用的 `ATaskTriggerVolume` 关卡辅助 Actor 统一处理，不要在每个关卡蓝图里重复连线。

> `ASuspectPawn` 已经内置了这个转发（见 7.7），不需要额外接线。

### 5.1 为什么 Sequencer 在 GameState，面板通道在 PlayerState

| 组件 | 挂点 | 原因 |
|---|---|---|
| `UTaskSequencerComponent` | GameState | 全局唯一、服务器权威、生命周期跟随对局 |
| `UScoreComponent` | GameState | 同上；分数是全队数据 |
| `UTaskPanelChannelComponent` | PlayerState | 需要 Owner 才能发 Server RPC；数据是“每人一份” |

> 记住：**GameState 上的组件不能发 Server RPC。** 这是本系统最容易踩的网络坑。

### 5.2 为什么任务不是 Actor

任务被设计成 `UObject`：

- 不需要每帧 Tick（全部事件驱动或低频 Timer）。
- 不需要复制（客户端不执行任务逻辑）。
- 可以内联在 DataAsset 里方便配表（`Instanced`）。

代价：

- 没有 `GetWorld()` 的默认实现 → 必须通过 Outer 链（`DuplicateObject(..., Sequencer)`）解决。
- 不能直接 `SetTimer` 到 Actor 上 → 用 `World->GetTimerManager()`。
- 生命周期要自己管 → Sequencer 负责结束和清理。

## 6. 核心概念

### 6.1 配表三层结构

```
UPrimaryTaskDataAsset
 └─ Steps[]                     // 顺序执行
     └─ FTaskStep
         ├─ ParallelTasks[]     // 同时启动，全部结束才推进
         └─ ScoreRules[]        // 错误码 → 扣分
```

### 6.2 任务模板 vs 任务实例

| | 模板 | 实例 |
|---|---|---|
| 谁创建 | 策划在 DataAsset 里内联创建 | `ExecuteStep` 里 `DuplicateObject` |
| Outer | DataAsset | Sequencer |
| 数量 | 每步 1 份 | 每步每次执行 1 份 |
| 状态 | 只读配置 | 运行时状态（定时器、已确认集合等） |
| 生命周期 | 跟随 DataAsset | 本步骤结束即废弃 |

**为什么必须复制**：如果不复制，第二局训练会带着上一局的状态（已确认集合、定时器句柄、已计分标记），导致“第二局一开始就跳过”。

### 6.3 身份（Role）与参训玩家（Participant）

- **Participant**：进场注册，`RegisterParticipant`。只有参与者参与“所有人都完成”的判定。
- **Role**：04 步由 `RoleSelect` 调 `AssignRole` 分配。一个 Role 只能被一个人占用。
- 分配成功后，服务器会往该玩家 Pawn 上 `AddUnique(RoleTag)`，方便“按 Tag 判定”的任务。
- **真相源**：`RoleAssignments`（TMap<FName, TWeakObjectPtr<APlayerController>>），Pawn Tag 只是投影。

### 6.4 任务的“结束”协议

所有任务结束都必须走：

```cpp
EndTask();  // BlueprintNativeEvent
```

`UMultipleTaskBase::EndTask_Implementation` 做了一件事：

```cpp
if (bTaskEnded) return;   // 防重复
bTaskEnded = true;
OnTaskEnd.Broadcast(this);
```

**任何自定义任务都必须调用 `Super::EndTask_Implementation()`**，否则 Sequencer 收不到完成通知，流程卡死。

### 6.5 步骤推进的时序

```
ExecuteStep(N)
 ├─ bStepStarting = true
 ├─ OnStepStarted.Broadcast(N)
 ├─ 阶段 1：Duplicate 所有 ParallelTasks，绑 OnTaskEnd（不启动）
 ├─ 阶段 2：依次 StartTask()
 ├─ bStepStarting = false
 └─ CheckStepCompletion()   // 处理“StartTask 内立刻结束”的任务

任务 A EndTask → HandleTaskEnd → CompletedTaskCount++
任务 B EndTask → HandleTaskEnd → CompletedTaskCount++
CompletedTaskCount == ActiveTasks.Num()
 └─ OnStepCompleted.Broadcast(N)
     └─ ExecuteStep(N+1)  或  OnAllStepsCompleted.Broadcast()
```

两个关键设计：

- **`bStepStarting`**：防止任务在 `StartTask` 里同步调用 `EndTask` 时，`CheckStepCompletion` 在“任务还没全部加进 ActiveTasks”时误推进。
- **`CompletedTaskCount < ActiveTasks.Num()`**：按数量比较，而不是“有没有任务在跑”，天然支持 0 任务步骤和空指针占位（空任务直接计数）。

## 7. 关键类详解

### 7.1 UPrimaryTaskDataAsset

文件：`Public/MultipleTask/Data/PrimaryTaskDataAsset.h`

| 结构 | 用途 |
|---|---|
| `FEquipmentInfo` | 装备展示信息（Id/名称/类/颜色），目前仅数据，不参与流程 |
| `FRoleStationPair` | 身份 → 站位 Tag（多人到位 / 就位确认共用） |
| `FRoleEquipmentTags` | 身份 → 装备 Tag 列表（领装 / 清点 / 选装共用） |
| `FScoreRule` | 错误码 → 扣分值 |
| `FTaskStep` | StepId / StepTitle / ParallelTasks / ScoreRules |

注意：

- `ParallelTasks` 是 `TArray<TObjectPtr<UMultipleTaskBase>>` + `Instanced` + `ShowOnlyInnerProperties`，所以编辑器里可以直接内联配置每种任务。
- 新增一个任务类型不需要改 DataAsset 结构，它会自动出现在“添加任务”的下拉里（只要 `UCLASS` 可见）。

### 7.2 UTaskSequencerComponent

文件：`Public/MultipleTask/TaskSequencerComponent.h`
挂点：`AGameStateBase`

#### 职责

1. 加载配表并顺序执行 Step。
2. 管理 ActiveTasks 生命周期。
3. 管理参与者与身份。
4. 把 Overlap 事件转发给当前步骤的所有活跃任务。
5. 提供按 Tag 查 Pawn / Actor 的查询接口。
6. 提供评分规则查询。

#### 关键成员

| 成员 | 复制 | 说明 |
|---|---|---|
| `CurrentTaskAsset` | 否 | 只在服务器使用 |
| `CurrentStepIndex` | 是（ReplicatedUsing） | 客户端 HUD 用；OnRep 里广播 `OnStepStarted` |
| `bIsRunning` | 是 | 客户端可判断是否在跑 |
| `ActiveTasks` | 否（Transient） | 仅服务器；当前步骤的任务实例 |
| `CompletedTaskCount` | 否 | 已结束任务数 |
| `bStepStarting` | 否 | 防重入 |
| `Participants` | 否 | 服务器侧弱引用 |
| `RoleAssignments` | 否 | 服务器侧身份映射 |
| `ReplicatedOccupiedRoles` | 是（ReplicatedUsing） | 客户端 UI 置灰用 |

#### 关键实现逻辑

**`StopAllTasks()` 的顺序不能改：**

```cpp
bIsRunning = false;          // 先关运行标记
bStepStarting = false;
CompletedTaskCount = 0;

TArray<...> TasksToStop = MoveTemp(ActiveTasks);
ActiveTasks.Empty();         // 再清空容器

for (Task : TasksToStop) { 解绑; Task->EndTask(); }
```

如果先 `EndTask()` 再清空，`HandleTaskEnd` 会在遍历容器时触发 `CheckStepCompletion` → `ExecuteStep` 重建 `ActiveTasks`，导致**迭代器失效崩溃**。这是已经修过的真实 bug。

**`ExecuteStep` 分两阶段**：见 6.5。不要改回“边创建边启动”。

**`FinishActiveTasksByClass`**：

```cpp
TArray<...> Snapshot = ActiveTasks;   // 快照，EndTask 会改容器
for (Task : Snapshot) if (!Task->bTaskEnded && Task->IsA(Class)) Task->EndTask();
```

用于“外部事件结束区域监控”这类任务（任务实例无法被外部直接拿到）。

**`FindScoreRule`**：先查当前步骤的 `ScoreRules`，再查全表。这样任务在切步瞬间上报也能找到规则。

#### 常见误用

- 在客户端调用 `LoadAndStartTask` / `RegisterParticipant`：会被 `HasAuthorityForTask()` 拒绝（日志 warning）。
- 直接改 `ActiveTasks`：不要。唯一入口是 `ExecuteStep` / `StopAllTasks`。

### 7.3 UMultipleTaskBase

文件：`Public/MultipleTask/TaskItems/MultipleTaskBase.h`

所有任务的根类。子类必须实现或调用：

| 成员 | 说明 |
|---|---|
| `StartTask_Implementation()` | 子类必须调用 `Super::StartTask_Implementation()`（复位 `bTaskEnded`） |
| `EndTask_Implementation()` | 子类必须调用 `Super::EndTask_Implementation()`（广播 OnTaskEnd） |
| `OnActorOverlapBegin/End` | 由 Sequencer 转发；默认空实现 |
| `FindPawnByRoleTag(FName)` | 通过 Sequencer 查身份对应 Pawn |
| `FindActorByTag(FName)` | 通过 Sequencer 查关卡 Actor（仅服务器） |
| `ReportScoreEvent(RoleTag, ErrorCode)` | 上报评分；任务不关心扣多少分 |
| `OwnerSequencer` | 由 Sequencer 注入，不要手动赋值 |
| `bTaskEnded` | 防重复结束 |

**`OnTaskEnd` 是 `BlueprintAssignable` 的动态委托**，Sequencer 用 `AddDynamic` 绑定。自定义任务如果在内部再绑一次，注意 `EndTask` 只广播一次。

### 7.4 UMultipleTask_PanelBase

文件：`Public/MultipleTask/TaskItems/MultipleTask_PanelBase.h`

面板类任务的基类。已实现：

- `PanelType / PanelTitle / PanelContent / PanelRows / PanelButtons`
- `Audience`（AllParticipants / SpecificRoles）
- `bHidePanelOnEnd`
- `PanelInstanceId = GetFName()`（每个运行时实例唯一）
- `PushPanelToAudience()` / `PushPanelToController()`
- `HidePanelFromAudience()`（只关自己的面板）
- `HandleChannelAction()`（校验 PanelId + audience 后再转给 `HandlePanelAction`）

子类只需要：

```cpp
FTaskPanelData BuildPanelData() const override;                                  // 填数据
void HandlePanelAction_Implementation(APlayerController*, FName ButtonId, int32 RowIndex) override; // 处理点击
```

**注意**：

- `BuildPanelData` 是 `virtual`（非 BlueprintNativeEvent），C++ 直接 override。
- `HandlePanelAction` 是 `BlueprintNativeEvent`，只能 override `_Implementation`，不要加 `UFUNCTION`。
- `PanelInstanceId` 用对象名，因为 DuplicateObject 生成的对象名唯一；如果以后改用对象池复用实例，需要换成 GUID。
- 并行面板只有“每人一个槽位”：同一玩家同时收到两个面板会互相覆盖。**不要在同一个 Step 里放两个面板任务。**

### 7.5 UTaskPanelChannelComponent

文件：`Public/MultipleTask/UI/TaskPanelChannelComponent.h`
挂点：`APlayerState`

#### 为什么这样设计

客户端 → 服务器的唯一通道是 Server RPC，而 Server RPC 要求组件有 Owner 链。
`AGameState` 没有 Owner；`APlayerState` 有（PlayerController），所以通道必须挂 PlayerState。

#### 数据流

```
服务器：
  ShowPanel(Data)  → CurrentPanel = Data; bPanelVisible = true;
                   → 非 DS 时手动 OnRep_PanelState()
客户端：
  OnRep_PanelState → OnPanelStateChanged.Broadcast(Panel, bVisible)
  UI 点击          → SubmitPanelButton(ButtonId, RowIndex)
                   → （客户端）Server_SubmitPanelButton(CurrentPanel.PanelId, ...)
服务器：
  Server_SubmitPanelButton
     ├─ 校验 PanelId == CurrentPanel.PanelId（丢弃过期点击）
     └─ SubmitPanelButtonInternal
          ├─ 要求 bPanelVisible
          ├─ 要求 GetOwningController() 有效
          └─ OnPanelActionSubmitted.Broadcast(PC, PanelId, ButtonId, RowIndex)
```

#### 防错设计

| 情况 | 处理 |
|---|---|
| 玩家点了旧面板上的按钮 | PanelId 不匹配 → 丢弃 |
| 面板已隐藏后点击 | `bPanelVisible == false` → 丢弃 |
| 并行任务互相关面板 | `HidePanel(PanelId)` 只关自己的 |
| 客户端伪造按钮 | 只会回传 `ButtonId`，任务侧还会校验 audience 与 ButtonId |

#### 自动创建

`FindOrCreateChannel(PC)`：

- 先找 PlayerState 上的组件。
- 找不到且服务器权威 → `NewObject` + `RegisterComponent`。
- 动态组件随 PlayerState 自动复制到客户端。

所以框架即使忘了在 PlayerState 蓝图上加组件，也能工作（首次注册参与者时创建）。

### 7.6 UScoreComponent

文件：`Public/MultipleTask/Score/ScoreComponent.h`
挂点：`AGameStateBase`

#### 数据

```cpp
struct FPlayerScoreEntry
{
    FName RoleTag;
    int32 FinalScore;             // BaseScore - TotalDeduction，最低 0
    int32 TotalDeduction;
    int32 ViolationCount;         // 上报次数
    TArray<FName> ViolatedErrorCodes; // 去重
};
```

#### 关键实现

- `ReportScoreEvent` 只接受服务器调用。
- 扣分值由 `ResolvePenalty` 通过 **Owner(GameState) 上的 Sequencer** 查询；所以 Sequencer 和 Score 必须挂在同一个 GameState 上。
- 规则找不到 → 日志 warning，按 0 分处理（不崩溃）。
- 没有该身份的记录时自动创建，初始 `BaseScore`。
- 每次上报后按 RoleTag 排序，保证 HUD 不跳行。
- 服务器本地不会触发 OnRep，`NotifyScoreChanged()` 手动广播一次（非 DS）。

#### 自动创建

`FindOrCreateScoreComponent(World)`：客户端返回 null；服务器在 GameState 上创建。

### 7.7 ASuspectPawn

文件：`Public/Actors/SuspectPawn.h`

- 根组件 `USceneComponent`
- `USkeletalMeshComponent`（美术挂模型/动画）
- `UBoxComponent TriggerBox`：
  - 相对位置 `(0,0,100)`，Extent `(100,100,100)`
  - `QueryOnly`，只对 `ECC_Pawn` Overlap，隐藏
  - **盒子大小就是“安全距离”**
- `UAudioComponent`
- `bReplicates = true`
- `BeginPlay` 绑定 Overlap → 只在 `ROLE_Authority` 转发给 Sequencer

**注意**：这个类在 `Actors/` 下，不属于任务系统逻辑，但它是目前唯一内置的场景交互 Actor。策划/美术调整安全距离只需要改 `TriggerBox` 尺寸。

### 7.8 UMultipleTask_ZoneMonitor

文件：`Public/MultipleTask/TaskItems/MultipleTask_ZoneMonitor.h`

区域监控抽象基类，统一了两种相反语义：

| 配置 | 语义 | 子类 |
|---|---|---|
| `bRequireInsideZone = true` | 必须留在区域内，离开 = 违规 | `StayInArea` |
| `bRequireInsideZone = false` | 必须待在区域外，进入 = 违规 | `KeepSafeDistance` |

已实现：

- Overlap Begin/End 判定（End 时用 `GetOverlappingActors` 复核，避免多碰撞组件误判）
- 违规玩家单独下发警告面板
- `PenalizedPawns` 保证每人每任务只扣一次分
- `RequiredCompliantDuration > 0` 时，全员合规持续 N 秒自动结束
- `FinishMonitoring()` 供外部结束
- `InitFromCurrentOverlaps()` 处理“任务开始时玩家已经在区域里/外”
- 单机兜底 `IsWatchedPawn`（未注册参与者时监控本地玩家）

`KeepSafeDistance` / `StayInArea` 只是构造里设默认值，**不要在这两个子类里重复实现逻辑**。

## 8. 三条完整数据流

### 8.1 步骤推进（服务器）

```
LoadAndStartTask(Asset)
 ├─ StopAllTasks()
 ├─ CurrentTaskAsset = Asset
 ├─ CurrentStepIndex = -1; bIsRunning = true
 ├─ ClearAllRoles()               // 新一轮重选身份
 ├─ ScoreComponent->ResetScores()
 └─ ExecuteStep(0)
      ├─ 清上一步残留 + ActiveTasks.Empty()
      ├─ CurrentStepIndex = 0        （复制 → 客户端 OnRep → OnStepStarted）
      ├─ OnStepStarted.Broadcast(0)
      ├─ Duplicate 所有任务，绑 HandleTaskEnd
      ├─ StartTask()
      └─ CheckStepCompletion()
```

### 8.2 面板按钮

```
[客户端] UI 按钮点击
  → Channel->SubmitPanelButton(ButtonId, RowIndex)
  → Server_SubmitPanelButton(CurrentPanel.PanelId, ButtonId, RowIndex)
      [服务器]
      → 校验 PanelId
      → 校验 bPanelVisible
      → OnPanelActionSubmitted.Broadcast(PC, PanelId, ButtonId, RowIndex)
      → PanelBase::HandleChannelAction
           → 校验 PanelId == PanelInstanceId
           → 校验 PC 在 audience 里
           → HandlePanelAction(PC, ButtonId, RowIndex)   // 子类实现
      → 业务处理（确认/选身份/结束）
```

### 8.3 违规扣分

```
[服务器] ZoneMonitor 检测到玩家离开/进入
  → SetPlayerViolating(Pawn, true)
      ├─ 下发警告面板（仅该玩家）
      ├─ PenalizedPawns 里没有该 Pawn → ReportViolation
      │    ├─ Pawn → RoleTag（Sequencer::GetRoleTagByPawn）
      │    └─ ReportScoreEvent(RoleTag, ViolationErrorCode)
      │         └─ ScoreComponent::ReportScoreEvent
      │              ├─ Sequencer::FindScoreRule（当前步骤优先）
      │              ├─ TotalDeduction += Penalty
      │              ├─ FinalScore = max(0, BaseScore - TotalDeduction)
      │              └─ NotifyScoreChanged → OnScoreBoardChanged
      └─ RefreshComplianceTimer()
```

## 9. 网络与复制

### 9.1 复制属性总表

| 类 | 属性 | 条件 |
|---|---|---|
| `UTaskSequencerComponent` | `CurrentStepIndex` | ReplicatedUsing `OnRep_CurrentStepIndex` |
| | `bIsRunning` | Replicated |
| | `ReplicatedOccupiedRoles` | ReplicatedUsing `OnRep_OccupiedRoles` |
| `UTaskPanelChannelComponent` | `CurrentPanel` | ReplicatedUsing `OnRep_PanelState` |
| | `bPanelVisible` | ReplicatedUsing `OnRep_PanelState` |
| `UScoreComponent` | `ReplicatedScores` | ReplicatedUsing `OnRep_Scores` |

### 9.2 不复制的东西（重要）

| 类型 | 为什么 |
|---|---|
| `TSubclassOf<>` / `TSoftObjectPtr<>` | 路径/类引用跨网络不可靠，且客户端不需要 |
| `TWeakObjectPtr` 容器 | 不支持复制 |
| `FTimerHandle` | 纯本地 |
| 任务实例与 `ActiveTasks` | 任务逻辑只在服务器执行 |
| `RoleAssignments` | 客户端只需要“哪些身份被占用” |
| `Participants` | 同上 |

### 9.3 服务器本地手动 OnRep

单机/监听服务器上，服务器写入复制属性**不会**触发自己的 OnRep。
所有“服务器写属性”的地方都做了：

```cpp
if (World->GetNetMode() != NM_DedicatedServer)
{
    OnRep_Xxx();
}
```

新增复制属性时，**必须复制这个模式**，否则单机调试时 UI 不刷新。

### 9.4 权威判断

- `UActorComponent` 没有 `HasAuthority()` 便捷函数，用：

```cpp
GetOwnerRole() == ROLE_Authority
```

- Actor 用 `HasAuthority()` / `GetLocalRole()`。
- `ASuspectPawn` 用 `GetLocalRole() != ROLE_Authority` 过滤掉客户端重复转发。

## 10. 二次开发指南

### 10.1 新增一个任务类型（最小步骤）

以“等 3 秒后自动完成”为例。

**Step 1：新建头文件** `Public/MultipleTask/TaskItems/MultipleTask_Delay.h`

```cpp
#pragma once

#include "CoreMinimal.h"
#include "MultipleTask/TaskItems/MultipleTaskBase.h"
#include "MultipleTask_Delay.generated.h"

UCLASS(CollapseCategories)
class POLICEPLATFORM_API UMultipleTask_Delay : public UMultipleTaskBase
{
    GENERATED_BODY()

public:
    virtual void StartTask_Implementation() override;
    virtual void EndTask_Implementation() override;

    // 等待时长（秒）
    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Delay", meta = (ClampMin = "0.0"))
    float DelaySeconds = 3.f;

private:
    FTimerHandle DelayTimerHandle;

    void OnDelayFinished();
};
```

**Step 2：新建实现文件** `Private/MultipleTask/TaskItems/MultipleTask_Delay.cpp`

```cpp
#include "MultipleTask/TaskItems/MultipleTask_Delay.h"
#include "Engine/World.h"
#include "TimerManager.h"

void UMultipleTask_Delay::StartTask_Implementation()
{
    Super::StartTask_Implementation();

    UWorld* World = GetWorld();
    if (!World)
    {
        UE_LOG(LogTemp, Warning, TEXT("[Delay] No world, ending immediately"));
        EndTask();
        return;
    }

    World->GetTimerManager().SetTimer(
        DelayTimerHandle, this, &UMultipleTask_Delay::OnDelayFinished, DelaySeconds, false);
}

void UMultipleTask_Delay::EndTask_Implementation()
{
    if (UWorld* World = GetWorld())
    {
        World->GetTimerManager().ClearTimer(DelayTimerHandle);
    }
    Super::EndTask_Implementation();
}

void UMultipleTask_Delay::OnDelayFinished()
{
    EndTask();
}
```

**Step 3：编译**，然后策划在 DataAsset 的 `ParallelTasks` 里点 `+` 就能看到 `MultipleTask Delay`。

**必须遵守的规则（每一条都对应过真实 bug）：**

1. `StartTask_Implementation` 第一行必须 `Super::StartTask_Implementation()`。
2. `EndTask_Implementation` 必须清理自己创建的所有定时器/委托，然后 `Super::EndTask_Implementation()`。
3. 定时器句柄必须是成员变量（`FTimerHandle` 作为局部变量无法取消）。
4. 所有 `UObject*` / `AActor*` 引用必须是 `UPROPERTY()`，否则会被 GC。
5. 动态委托必须 `AddDynamic` / `RemoveDynamic` 成对出现，且 EndTask 里解绑。
6. 不要在构造函数里访问 World / 启动逻辑。
7. 不要用 Tick（UObject 没有）；需要轮询用 `SetTimer`。
8. 不能写 `TArray<bool>` 的 `UPROPERTY`（UHT 不支持），用普通成员。

### 10.2 新增一个面板类任务

```cpp
// .h
UCLASS(CollapseCategories)
class POLICEPLATFORM_API UMultipleTask_MyPanel : public UMultipleTask_PanelBase
{
    GENERATED_BODY()

public:
    virtual FTaskPanelData BuildPanelData() const override;
    virtual void HandlePanelAction_Implementation(
        APlayerController* PC, FName ButtonId, int32 RowIndex) override;

    UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Panel")
    FText ConfirmButtonText;
};

// .cpp
FTaskPanelData UMultipleTask_MyPanel::BuildPanelData() const
{
    FTaskPanelData Data = Super::BuildPanelData();   // 先取通用字段

    FTaskPanelButton Button;
    Button.ButtonId = FName(TEXT("Confirm"));
    Button.Label = ConfirmButtonText;
    Data.Buttons.Add(Button);

    return Data;
}

void UMultipleTask_MyPanel::HandlePanelAction_Implementation(
    APlayerController* PC, FName ButtonId, int32 RowIndex)
{
    if (ButtonId == FName(TEXT("Confirm")))
    {
        EndTask();
    }
}
```

要点：

- `Super::BuildPanelData()` 会带上 PanelId/Type/Title/Content/Rows/Buttons，不要从零构造。
- 不要在 `BuildPanelData` 里改任务状态（它是 const）。
- 点击处理里要校验 `ButtonId`，否则额外按钮也会触发逻辑。
- 面板下发用 `PushPanelToAudience()`；内容变化时重新调用即可。
- 需要只给某个玩家提示（如警告），用 `PushPanelDataToController(PC, Data)`。

### 10.3 新增区域类任务

继承 `UMultipleTask_ZoneMonitor`，构造函数里设默认值即可：

```cpp
UMultipleTask_MyZone::UMultipleTask_MyZone()
{
    ZoneActorTag = FName(TEXT("MyZone"));
    bRequireInsideZone = true;
    ViolationErrorCode = FName(TEXT("MyViolation"));
    PanelType = EUIPanelType::ScenePrompt;
}
```

不要重写 Overlap 逻辑，除非你确实需要新的区域语义。

### 10.4 新增错误码

1. 任务里配置/上报新的 `FName` 错误码。
2. 策划在对应 Step 的 `ScoreRules` 里加同名规则。
3. 不需要改 C++。

如果需要“同一类错误只扣一次”，参照 `ZoneMonitor::PenalizedPawns` 存已处理 Pawn。

### 10.5 新增 Sequencer 事件

如果框架需要感知新事件：

1. 在 `TaskSequencerComponent.h` 顶部声明动态委托。
2. 加 `UPROPERTY(BlueprintAssignable)` 成员。
3. 在合适位置 `Broadcast`。
4. 注意：如果事件只在服务器发生，客户端需要的话必须走复制属性 + OnRep（参考 `OnRep_CurrentStepIndex`）。

## 12. 调试与排错

### 12.1 日志关键词

统一用 `UE_LOG(LogTemp, ...)`，搜索这些前缀：

| 前缀 | 来源 |
|---|---|
| `[TaskSequencer]` | 加载、步骤开始/完成、身份分配、参与者注册 |
| `[PanelBase]` | 面板通道缺失 |
| `[Score]` | 扣分、规则缺失 |
| `[PlayAudio]` | 目标/音频缺失 |
| `[PlayAnim]` | 动画缺失/不支持类型 |
| `[NPCBehavior]` | 移动结果、NPC 缺失 |
| `[StationConfirm]` | 到位/离开 |
| `[EndTraining]` | 玩家选择 |

### 12.2 常见现象与定位

| 现象 | 最可能原因 | 检查位置 |
|---|---|---|
| 流程停在某步 | 该步有任务永不结束 | 看任务字段：AutoCloseDelay=0、RequiredCompliantDuration=0、无按钮、身份缺席 |
| 面板不显示 | 玩家没注册 / 通道没创建 / UI 没绑事件 | `RegisterParticipant` 日志、`FindOrCreateChannel`、框架 UI |
| 点按钮没反应 | PanelId 过期 / 按钮不在当前面板 / 任务未处理该 ButtonId | `Server_SubmitPanelButton` 断点 |
| 第二局直接跳到后面 | 任务模板被复用（Duplicate 失效/被改坏） | `ExecuteStep` 里是否还在 Duplicate |
| 扣分不生效 | 错误码没有配规则 | `[Score] ... has no score rule` |
| DS 上 UI 不刷新 | 误用本地 UI / 没触发 OnRep | 检查 `NotifyScoreChanged` / `OnRep_PanelState` 的 NM_DedicatedServer 判断 |
| 崩溃在 StopAllTasks | 迭代中推进步骤 | 确认 `bIsRunning=false` 在最前、`MoveTemp` 快照 |
| 定时器回调崩溃 | 局部 FTimerHandle / EndTask 没 ClearTimer | 搜索 `FTimerHandle Dummy` |
| 动画/音频不播 | Outer 非法 / 目标没有组件 | `NewObject` 的 Outer 必须是 Actor，位置音用 `SpawnSoundAtLocation` |

### 12.3 推荐的断点位置

1. `UTaskSequencerComponent::ExecuteStep` — 看步骤是否正确实例化。
2. `UTaskSequencerComponent::HandleTaskEnd` — 看哪个任务没结束。
3. `UTaskPanelChannelComponent::Server_SubmitPanelButton_Implementation` — 看按钮是否到达服务器。
4. `UMultipleTask_PanelBase::HandleChannelAction` — 看是否被 PanelId/audience 过滤。
5. `UScoreComponent::ReportScoreEvent` — 看错误码与扣分。

### 12.4 单机调试技巧

- 未注册参与者时，`Audience=AllParticipants` 会自动退化为本地玩家（仅 `NM_Standalone`）。
- `ZoneMonitor::IsWatchedPawn` 有单机兜底，不用注册也能测。
- 用 `SkipToStep(N)` 直接测某一步，不用从头跑。
- 用 `FinishActiveTasksByClass(UMultipleTask_KeepSafeDistance::StaticClass())` 手动结束监控。

## 13. 已知限制与设计取舍

| # | 限制 | 影响 | 后续建议 |
|---|---|---|---|
| 1 | 每个玩家的面板通道只有 1 个槽位 | 同一 Step 放两个面板任务会互相覆盖 | 需要并行多面板时改成 `TMap<FName, FTaskPanelData>` |
| 2 | `PanelInstanceId = GetFName()` | 依赖对象名唯一；对象池复用会冲突 | 改用 `FGuid` 或自增 ID |
| 3 | 语音识别完全依赖外部 | 不接 SDK 时只会超时重试 | 封装一个 `IVoiceProvider` 适配层 |
| 4 | Sequencer 没有静态 `FindOrCreate` | 框架必须手动在 GameState 上加组件 | 可补一个 `FindOrCreateSequencer(World)` |
| 5 | 客户端拿不到 Role 映射 | `GetRoleTagByPawn` 在客户端返回 None | 需要的话把映射做成复制结构 |
| 6 | 任务没有 Tick | 高频逻辑需要 Timer | 保持现状，避免性能问题 |
| 7 | `SetAIState` 只是占位 | NPC 状态切换需要蓝图扩展 | 改成 BlueprintImplementableEvent |
| 8 | 搜身高亮未实现 | `HighlightColor` 未使用 | 用 `BlueprintImplementableEvent` 暴露给蓝图 |
| 9 | 装备 Tag 依赖物品侧 | 物品没贴 Tag 则装备任务永不满足 | 在物品拾取/丢弃处统一封装 |
| 10 | `FText` 直接复制 | 多语言切换需要重新下发面板 | 文案 Key 化后再本地化 |

## 14. 编码规范

### 14.1 命名

- 任务类：`UMultipleTask_Xxx`，文件同名。
- 配表结构：`F` 前缀，放 `PrimaryTaskDataAsset.h`（跨任务复用的）或任务自己的头文件（专用的）。
- 布尔：`bXxx`。
- Tag 字段：`XxxTag`。

### 14.2 UPROPERTY 规则

- 所有 `UObject*` / `AActor*` 成员必须 `UPROPERTY()`，否则 GC 后悬空。
- 需要策划配的字段：`EditDefaultsOnly` + `BlueprintReadOnly`。
- 需要运行时读写：`BlueprintReadWrite`。
- 容器里存 `TObjectPtr`，不要裸指针。

### 14.3 生命周期规则

- `StartTask_Implementation` 只做“启动”，不做阻塞等待。
- `EndTask_Implementation` 必须幂等（可能被 Stop、Skip、自然结束多次触发）。
- 所有异步回调（Timer、委托、音频结束）都要能在 EndTask 后安全返回：
  - 清定时器；
  - 解绑委托；
  - 回调开头检查 `bTaskEnded`。

### 14.4 网络规则

- 服务器函数入口先判断 `GetOwnerRole() == ROLE_Authority`。
- 客户端不要直接改复制属性。
- 新增复制属性时：
  - `SetIsReplicatedByDefault(true)`（构造函数）
  - `DOREPLIFETIME`
  - 服务器写入后手动触发 OnRep（非 DS）
- 不要把 `TSubclassOf` / `TSoftObjectPtr` 放进复制结构。

### 14.5 解耦规则

- 不 include 框架头文件。
- 不写平台判断。
- 不直接引用物品类：用 Pawn Tag。
- 不直接切场景/重开：用 `NotifyChoiceMade` 抛给框架。
- 需要美术表现时，优先加 `BlueprintImplementableEvent`，不要在 C++ 里写死特效。
