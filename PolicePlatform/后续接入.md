## 一、方案总览：三层职责模型

| 层 | 承担者 | 职责 |
|---|---|---|
| **生命周期壳** | 框架 AC_Task + 一个静默任务 | 启动时钟（等像素流客户端加入）、整场限时（TimeLimit）、结束收尾（训练结束上报、Logout 关房检查） |
| **任务内核** | MultipleTask TaskSequencer | 所有真实任务步骤推进、评分、UI 驱动 |
| **上报枢纽** | GameState（服务器端） | 组装 FTaskResult → WSSubsystem → 中心DS → 教练端 |

**对框架的侵入**：零 C++ 修改，桥接全部写在课件插件的蓝图层。

## 二、方案点 1：静默任务桥接（生命周期同步）

### 2.1 完整时序

```
教练端"开始训练" → 房间DS 拉起 → 学员+像素流客户端进齐
  → 课件蓝图调 AC_Task.StartTasks()            ← 旧系统当唯一时钟源
  → 静默任务 OnTaskStart_BIE 激活
      → 此处调 Sequencer.LoadAndStartTask(DA)  ← 你的系统从静默任务里被拉起
      → "等像素流客户端加入"硬约束自动被继承

Sequencer 全部步骤完成（服务器 GameState 上 OnAllStepsCompleted）
  → 调 AC_Task.EndCurrentTask(映射后的 ETaskResult)
  → 静默任务是 TaskClassList 最后一个 → OnAllTasksCompleted
  → 走框架完整收尾链路（训练结束上报 → 学员退出 → Logout 关房 → 中心DS回收端口）
```

**同侧同进程直调**：GameState → 遍历找 Pawn → 拿 AC_Task，不需要 RPC。

### 2.2 三个必须补的坑

| # | 坑 | 处理 |
|---|---|---|
| 1 | **双向终止缺失**：静默任务超时/踢人中断时 Sequencer 还在跑 | 静默任务结束回调里反向调 `Sequencer.StopAllTasks()`（清理定时器和任务实例） |
| 2 | **暂停训练打不到你的系统**：`OnTrainPaused` + 移除输入映射只对旧系统生效 | `OnTrainPaused` 桥接 → Sequencer 暂停（**系统需要补暂停/恢复接口**，见 §5.1） |
| 3 | **结果映射**：EndCurrentTask 需带 ETaskResult（Succeed/Fail/TimeOut） | 桥接蓝图里把 Sequencer 最终结论映射成对应枚举，否则教练端看到的是静默任务默认值 |

### 2.3 副产品：整场限时

静默任务的 `TimeLimit` 直接当整场训练限时用——超时自动结束并触发双向终止，中心DS 每 5 秒的计时校准机制自动覆盖。

### 2.4 待决策：静默任务勾不勾 IsKeyTask

- **勾（推荐倾向）**：结束自动上报一条 TaskScore，复用框架链路零上报代码；TaskName 起有意义的名字（如"综合处置演练"），FTaskData 分数留 0，中间过程评分靠 §三 的上报通道补——两条通道互补不重复
- **不勾**：结束只走状态上报，所有分数全靠自己组装上报，显示更精确但代码更多

## 三、方案点 2：上报通道（GameState 服务器端转发）

### 3.1 为什么必须走服务器端

WSSubsystem 是 GameInstanceSubsystem，**每进程一份、互不复制**，客户端那份没有意义。服务器上任何 Actor 都能 `GetGameInstance → GetSubsystem<UWSSubsystem>()` 拿到。TaskSequencerComponent 本来就挂在 GameState 上，上报逻辑与任务驱动放一起内聚性最好。

> 小纠偏：AC_Task 挂在 **PPPlayerBase（Pawn）** 上，不在 GameState。桥接路径：`GameState → Pawn → AC_Task`。

### 3.2 上报链路

```
Sequencer 关键步骤得分（服务器，OnScoreBoardChanged / ReportScoreEvent）
  → 组装 FTaskResult
      SN     ← InfoSubsystem.PlayerInfo
      MapID  ← RoomDSInfo.MapID
      RoomID ← RoomDSInfo.RoomID
      TaskIndex / TaskResult / Score / Keywords / YYSpeak 按 Sequencer 数据填
  → WSSubsystem.WS_SendTaskScoreToCenterDS
  → 中心DS WSJson_TaskScore
  → 教练端 OnTaskScoreReceivedDelegate → 实时播报 UI
```

### 3.3 多学员扩展点

`FTaskResult.SN` 按学员区分。**当前按一房一学员设计**（与 Sequencer 房间级单实例模型自洽）；将来一房多独立学员时，遍历 ScoreComponent 分数表按 SN 逐个组装上报。

## 四、与框架旧系统的共存边界

| 维度 | 旧 AC_Task | MultipleTask | 共处方式 |
|---|---|---|---|
| 挂载 | Pawn 上，每人一份 | GameState 上，房间一份 | 互不干扰 |
| 数据 | UCourseDefinition / TaskClassList | UPrimaryTaskDataAsset | 静默任务用前者，真任务用后者 |
| 驱动 | 静默任务只作时钟壳 | Sequencer 驱动全部真任务 | **同一课件任务流二选一驱动**，避免 UI/旁白双触发 |
| 上报 | 框架通道被桥接复用 | 走 §三 的桥接 | 只接一套，防教练端播报重复 |
| 暂停 | OnTrainPaused + 移除输入映射 | 需桥接进 Sequencer | 见 §5.1 |

**静默原则**：除静默任务外，旧系统不调 StartTasks 后续任务、CourseDefinition 不设任务序列、语音上报/装备开关等旧通道不与新任务类同时触发。
